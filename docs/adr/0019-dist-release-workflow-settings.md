# ADR 0019: Releases are built by a generated dist workflow, published last, and gated by an artifact check

- Status: Accepted (2026-10-28, M1-007). Needs security-reviewer sign-off on decisions 4 and 5. Amends the dist settings in 06, Appendix B.
- Date: 2026-10-28

## Context

M1-007 turns `dist` 0.33.0 on for the five targets. Running `dist init` and `dist generate` and reading
the workflow it writes showed that four settings in 06, Appendix B do not do what the plan assumed. The
sandbox run is a manual step (see 06, "Sandbox proof"), so these are read from the generated file and a
local build, not from a sandbox run.

## Decision

1. `release.yml` is generated by `dist generate` from `dist-workspace.toml` and is never edited by hand.
   `dist` is pinned to 0.33.0. Every action in it is pinned to a commit SHA through
   `[dist.github-action-commits]`. On a pull request the workflow only plans, and the plan job fails if
   the file has drifted from the config.
2. `github-release = "announce"`, not `"host"`. In 0.33.0, `"host"` runs `gh release create` in the host job,
   so the release is public before any publish job runs, and a signature added later would come after
   publication. `"announce"` creates the release in the last job, from the workflow's artifacts, after
   every publish job. This also answers the open question in 06 about immutable releases: dist does
   publish first unless it is set to `"announce"`.
3. The artifact check is a **publish job**, not a host job. In 0.33.0 the announce job waits for publish
   jobs and stops if one fails, but it ignores a failed host job. `publish-prereleases = true`, because
   otherwise dist skips publish jobs on every `-alpha.N` tag and announce treats a skipped job as passed.
   The check is `scripts/check-release-artifacts.sh`. It includes `scripts/check-static.sh` on both Linux
   archives, because a linker override such as `cargo-zigbuild` bypasses `scripts/musl-pie-linker.sh`
   (ADR 0006, decision 2). It also checks hashes, archive paths, each binary's format and CPU,
   the Windows imports, `cargo audit bin` and the SBOM.
4. `github-attestations` stays off. It adds `id-token: write` to the build jobs, and 06 says the signing
   job is the only job that has it. The cosign signature of `SHA256SUMS` (M1-010) is the trust path.
   Revisit in M2.
5. Accepted gaps, for security-reviewer to confirm, and for M1-010 to close or re-accept:
   - dist writes `permissions: contents: write` for the whole workflow, so the build jobs hold a write
     token. dist has no setting for this. Options: `allow-dirty = ["ci"]` plus a checked post-processing
     step, or the hand-written workflow that 06 names as the fallback.
   - dist, `cargo-auditable` (from `latest`) and `cargo-cyclonedx` are installed by `curl | sh` from
     release URLs with no hash. A compromised tool changes the binary before it is signed. The artifact
     check cannot see that. M2 hand-writes the install steps with pinned hashes, or replaces the workflow.
   - `.github/zizmor.yml` ignores five rules for `release.yml` only (excessive-permissions,
     template-injection, unpinned-images, secrets-inherit, self-repository). Every other rule and every
     other file stays checked.
6. `aarch64-apple-darwin` is built on `macos-15-intel` with plain `cargo` (dist uses no wrapper from
   Darwin to Darwin) and is never run there (ADR 0006, decision 8). The check reads the Mach-O header for
   the arm64 CPU type. A smoke run on arm64 waits for the founder hand step.
7. The SBOM is CycloneDX **XML** (`rdy.cdx.xml`). dist runs a fixed `cargo cyclonedx -v`, which writes XML,
   and has no setting for JSON. The ticket's exit test says JSON; the correction is "valid CycloneDX".
   A JSON SBOM per target can come from `auditable2cdx` in `sign-release` (06, SBOM section).
8. `[profile.dist]` inherits `release` with thin LTO, one codegen unit and stripped symbols. Unwinding
   stays on, because the scheduler isolates a panicking check with `catch_unwind`. The cargo-auditable
   data survives `strip` (checked on the x86_64 musl build: 63 dependencies listed).

## Consequences

- A tag must equal a package version (`v0.1.0-alpha.0` today). Bump the crate versions before tagging
  `-alpha.N`, per ADR 0007.
- The SBOM holds the build path of the runner in `bom-ref` values. It is public. Appendix D lists it.
- Bumping `dist` is a deliberate change: edit the version, run `dist generate`, review the diff, update the
  zizmor ignores if the generated file moved.

## Alternatives considered

| Option | Why it lost |
| --- | --- |
| Hand-written release workflow now | About a day, outside M1-007. Stays the fallback if dist stalls or decision 5 cannot be closed. |
| Post-process `release.yml` (permissions, tool hashes) | Needs `allow-dirty = ["ci"]`, which turns off dist's drift check, and its own drift check in CI. Left to M1-010. |
| Check as a host job | A failed host job does not stop announce (decision 3). |
| `github-attestations = true` | Breaks the one-job `id-token` rule (decision 4). |
