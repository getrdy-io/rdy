# Rdy check catalog

Every check at launch, grouped by family. Written by check-author. Revised 2026-10-28 after review by rust-engineer (host, net), k8s-expert (section 4), cloud-iam-expert (section 5) and gpu-expert (section 6 and `k8s.device_plugins`), and aligned with `02-engine-design.md`, which owns the Check trait, the probe facade and the verdict rule. This file only says what each check needs from them in one line.

How to read this: section 1 holds the rules for every check. Sections 2 to 8 are the families, each ordered by how often that check catches a real install failure (my field judgement, to be re-ranked with portal failure data after M2). Each check has the same six bullets. Appendices list every shell-out and every data file the checks ship.

## 1. Conventions

**Ids.** `<family>.<name>`, lowercase, snake_case name, stable forever (a rename keeps the old id as an alias for one major spec version). Families: `host`, `net`, `k8s`, `gpu`, `store`, `custom`. Cloud checks use the provider as the prefix, not `cloud.`: `aws.iam`, `gcp.iam`, `azure.rbac`. This matches the plan's example spec. In this catalog and in the crate (`rdy-checks-cloud`) they are the "cloud" family. The vendor-command check is `custom.exec` (ADR 0005), M4.

**Tiers.**

| Tier | Meaning |
| --- | --- |
| M1 | In the six-week alpha. Needed for the "one design partner catches a real blocker" exit test. |
| M1-late | Inside the M1 families, but first to slip to the start of M2 if hours run out. |
| M2 to M5 | Not in the alpha. Custom file M2, cloud M3, store M3, `custom.exec` M4, GPU M4. |

**Capacity and cut order.** Plan hours for M1 are 60 to 90 (six weeks at 10 to 15 hours). About 42 of those go to workspace, spec, engine, report, signing and release, leaving 18 to 48 hours for checks. The review pass made the real cost clear:

| Tier | Plumbing | Host | Net | K8s | Total |
| --- | --- | --- | --- | --- | --- |
| M1 | 22 | 19 | 18 | 20 | 79 hours, plus 6 hours of reviews |
| M1-late | 0 | 35 | 17 | 20 | 72 hours |

Even the `M1` tier is about twice the window. It does not include the engine and facade tickets in `02-engine-design.md` or the two Kubernetes client tickets in ADR 0010 (about 7 more hours). The founder must choose: a longer M1, or a smaller one. Cut order if hours run short, first cut first, with hours saved:

1. `host.cpu` flags and cgroup quota detail (keep core count and arch): 1h.
2. The free-capacity half of `k8s.nodes` (cluster-wide Pod list, often forbidden anyway): 2h. Then the kubelet-skew part of `k8s.version`: 0.5h.
3. `host.ports` owner lookup (keep conflict detection): 1h.
4. `net.proxy` sources beyond the process environment and the systemd drop-ins for docker, containerd and kubelet: 1h.
5. The OS-store classification in `net.tls_intercept` (keep issuer and chain depth reported by `net.egress` on `tls_unknown_issuer`): 2h.
6. The macOS and Windows sysinfo subset: 3h.

Never cut: `host.os`, `host.disk`, `host.memory`, `net.egress`, `k8s.access`, `k8s.rbac`, `k8s.storageclass`. In particular `k8s.rbac` is the cheapest and most vendor-specific k8s check, and `net.tls_intercept` is the plan's headline network check.

**Result words.** These are the engine's (02). A check returns a level (pass, warn, fail) from its thresholds. The spec `severity` then caps it: `severity: warn` turns a fail into warn (and is how a spec says "optional"), default is `block`. Status is `Pass`, `Warn`, `Block`, `Skipped(reason)`, `Timeout` or `Error`, plus a `partial` flag. Skip reasons: `MissingNeed`, `NotYetOnOs`, `NotApplicable`, `NeedsNewerRdy`, `RunDeadline`, `Cancelled`. **Verdict rule (02):** a block-severity check that is skipped for any reason except `NotApplicable`, or that times out, or errors, makes the run NOT READY, exit 2, counted as "required check not run". `NotApplicable` is for concepts that do not exist (SELinux on Windows) and for the spec `os` filter, never for "I could not look". A check that cannot examine something the spec requires returns a block or a warn with the reason, not `NotApplicable`. The earlier `require` and `optional` flags are gone for that reason.

**Common spec fields** (`01-spec-format.md` owns the final list): `id`, `severity`, `fix` (replaces the built-in remediation text verbatim, with no templating), `timeout`, `os`. Everything else is per check, listed under Thresholds.

**Units.** Bytes use binary suffixes (`32Gi`). Network rates are megabits per second (`Mbit/s`). Durations are `5s`, `7d`.

**Shape of `observed` and `expected`.** The result schema bounds them: at most 64 keys, a value is a scalar (text at most 4 KiB) or a list or object of at most two more levels, and each list holds at most 256 items and each object at most 64 keys. A check that can find more (nodes, mounts, interfaces) keeps the first 256 items in the order it read them, and says so in a `notes` entry. The writer cuts what a check leaves over and sets `truncated`, but a check should not rely on that (M1-055).

**Nominal band.** Humans write nominal sizes. A "32 GB" VM shows about 31.3 GiB in `MemTotal`, a "4 GB" VM about 3.8 GiB, a "24 GB" L4 or A10G about 22.5 GiB of VRAM with ECC on. So size checks have a band below `min`, and a value inside it counts as pass with a note: memory `max(5%, 256 MiB)`, VRAM 8%. Spec field `band` overrides it, `band: 0` turns it off, and `band_result: warn` makes a vendor see a warn instead of a pass. The band is never wider than half of `min`, so a tiny value always blocks. Spec authors should write the real need, not the marketing size.

**Degrade rule (02, needs rule 4).** A hard need (`needs`) missing: the check does not run (`Skipped MissingNeed`). A soft need (`wants`) missing, or a source unreadable (permission denied, tool missing, API forbidden): the check runs, returns what it could read, sets `partial`, and names the grant that would complete it. A partial check never blocks on data it could not read. If the unread data could have turned a pass into a block, the check returns Warn "not verified: X", never Pass. Windows or macOS data that needs admin is `partial`, not `skipped`.

**Needs line.** Each check ends its Needs bullet in engine vocabulary: `needs:` (hard `Need`s: `Root`, `KubeContext`, `Network`, `Command(name)`, `CloudCredentials(provider)`), `wants:` (soft), and the timeout. The Source bullet is the check's side-effect manifest (`CheckInfo` reads, commands, env, peers); a test asserts that every fixture run stays inside it.

**Bounds, for every check.** Read-only. Default timeout 5s for local reads, 15s for network probes, 30s for Kubernetes list calls, 60s hard cap. Files read are capped at 1 MiB. Command output capped at 1 MiB. Evidence lists cap at 200 items with a "truncated" flag. A syscall that can hang (NFS `stat` and `statvfs`) runs on `spawn_blocking` under the timeout and reports `Timeout`; the thread is abandoned and the runner ends the process hard after the report is written.

**Probe facade (02).** Every exec, file read, environment read, native OS call, socket, DNS lookup and Kubernetes request goes through `Probe`. Checks never call `std::fs`, `std::process`, `std::net`, `std::env` or `tokio::net` (clippy `disallowed-methods`). Network checks do not use `reqwest`: they run `tokio-rustls` and `hyper` client connections over a `ProbeStream`, with the CONNECT request written by us. Redirects are never followed; a `Location` host that the spec does not list is recorded as evidence and the text says "redirects to `{host}`; add it to endpoints to test it". Facade calls available to checks: `read`, `read_tail`, `read_dir`, `read_link`, `stat`, `env`, `exec`, `lookup`, `connect`, `native` (statvfs, uname, adjtimex, rlimit, available parallelism, sysinfo snapshots, Windows registry; each returns plain structs, never `sysinfo` or `rustix` types, so a fixture can build them by hand), and the Kubernetes guard layer. Gaps in the facade are listed under "Decisions needing an ADR", addressed to rust-architect.

**Command policy (02).** Fixed argv, no shell, program resolved from the fixed search path (`/usr/sbin:/usr/bin:/sbin:/bin`; on Windows `%SystemRoot%\System32`), cleared environment plus `LC_ALL=C`, stdin null, own process group, wall timeout and kill, 1 MiB stdout cap. The facade refuses `sh`, `bash`, `cmd`, `powershell`, `pwsh`, `sudo` and similar, so this catalog uses no PowerShell anywhere. Any argument that comes from the spec (sysctl names, host names, paths) first passes an allow-list regex. Appendix A lists every command.

**Redaction in evidence.** First line, in each check: every URL stored in evidence is `scheme://host:port/path` only (no userinfo, no query, no fragment); environment variables are recorded by name, not value, except an allow-list (proxy variables with userinfo stripped, `NO_PROXY`); kubeconfig tokens, DSNs, cloud keys and request bodies never enter a result; files holding credentials (`~/.docker/config.json`) are deserialized into a struct that has only the fields the check needs. Second line: `rdy_engine::redact` runs over the whole report (02). Host names and IPs of customer proxies and name servers appear in reports on purpose: they are what the fix needs.

**Scope of host and net.** Host and net checks describe the machine running `rdy`, which may be a bastion and not the target node. The report says which machine it was.

**Fixtures.** Layout follows the Replay backend in 02: `tests/fixtures/<check-id>/<case>/` with `root/` (fake file tree; `/proc/meminfo` is `root/proc/meminfo`), `commands/*.json` (`{argv, stdout, stderr, exit, delay_ms}`; file names are a readable slug plus a hash of argv, because raw argv breaks Windows file names), `net.json` (scripted outcomes per `host:port`: `refused`, `blackhole`, `reset`, `serve: <name>`), `native/` (recorded JSON per api name), `env.json`, `caps.json`, `api/` (recorded Kubernetes or cloud responses), and `expect.json` (golden result). Rules: virtual paths are POSIX strings so one fixture runs on all four CI targets; a `root.manifest.json` adds what git cannot store, as `symlinks: {"proc/1234/fd/7": "socket:[8841]"}`, `unreadable: ["var/log/audit/audit.log"]` and `dirs`, materialised in memory only; golden files with generated values (rcgen serials, SHA-256 of generated roots) use placeholders such as `"<sha256>"` in the compare helper; recorded output from real machines is rewritten to acme names before commit. Everything is synthetic: acme names, `*.example` hosts, fake tokens such as `REDACTED-TEST-TOKEN`. Each fixture list below is the minimum case set. Every check with a secret-bearing source also gets a planted-secret golden test.

**Shared helpers.** Dotted version compare, quantity parsing, nominal band and severity cap live in one module that `rdy-checks-host`, `rdy-checks-k8s` and `rdy-checks-gpu` can all use without depending on each other. The cgroup helper lives in `rdy_checks_host::cgroup`, because all three users are host checks. It joins `/proc/self/cgroup` with `/proc/self/mountinfo`, takes the minimum along the parent chain, treats v2 `max` and v1 `9223372036854771712` as unlimited, and reads `memory.swap.max`. It serves `host.memory`, `host.cpu` and `host.cgroups`. Data files in Appendix B are embedded. Every sysctl name and command that appears in fix text is checked against an allow-list file in CI, so a typo fails the build: `crates/rdy-engine/src/fixtext/{commands,sysctls,literals}.txt`, read by `rdy_engine::fixtext` (ADR 0028). Appendix A is held equal to the typed command table in `rdy_engine::exec::table` by `crates/rdy-engine/tests/command_table.rs`.

## 2. Host family (`rdy-checks-host`)

Linux is the first-class target. On macOS and Windows, M1 ships a sysinfo-only subset of four checks (`host.memory`, `host.cpu` cores and arch, `host.disk` free space, `host.os` name and version), so the four-OS CI runs real code; the rest is `NotYetOnOs` until the M1-late catch-up tickets, or `NotApplicable` where the concept does not exist. "Not applicable" below means that.

| Order | Id | Tier | Privilege | One line |
| --- | --- | --- | --- | --- |
| 1 | `host.disk` | M1 | none | Free space, inodes, mount flags per path |
| 2 | `host.memory` | M1 | none | RAM, swap, cgroup limit |
| 3 | `host.ports` | M1 | wants Root | Required ports free |
| 4 | `host.lsm` | M1-late | wants Root | SELinux and AppArmor state, recent denials |
| 5 | `host.security_agents` | M1-late | wants Root | Security software processes that inspect file and process activity |
| 6 | `host.firewall` | M1-late | wants Root | Host firewall active, inbound ports allowed |
| 7 | `host.time_sync` | M1-late | none | Clock sync state and offset |

| 9 | `host.sysctl` | M1-late | none | Kernel parameters and limits |

### host.disk (M1)
- **Measures:** free bytes and free inodes on the filesystem holding each required path (nearest existing parent if the path does not exist yet), filesystem type, mount flags (`noexec`, `nosuid`, `ro`), network filesystems.
- **Source:** L: `statvfs(2)` through `native` (`f_bavail * f_frsize`, `f_files`, `f_ffree`, and `f_flag` for `noexec`, `nosuid`, `ro`; on macOS `statvfs` reports `nosuid` and `ro` only, so `noexec` is `None` there (unknown) and `noexec: forbid` reports "not verified", not a pass); `/proc/self/mountinfo` for fstype names (decode octal escapes such as `\040`; use the mount point, field 5; match whole path components, so `/var` does not match `/variable`; resolve symlinks first). The manifest declares `statfs: ["/"]` and `reads: ["/proc/self/mountinfo"]` (M1-171): `Statvfs` is judged by `statfs`, so the check measures any spec path and cannot read a file there. On macOS a directory the user can search but not read is measured through its parent when that is on the same device, and otherwise the path reports "not verified: cannot open the directory" (`ProbeError::PermissionDenied`), never a failure or a guess. The nearest-parent walk and `canonicalize` run inside the `spawn_blocking` closure, because `stat` on a hung NFS mount blocks too. M: `sysinfo` disks plus `statvfs` flags. W: `sysinfo` disks (free space); a path starting with `\\` is a network share, anything else is not detected as one in M1; inodes and `noexec` not applicable on NTFS.
- **Needs:** none, timeout 5s per path. Evidence says "root-reserved blocks included" when `rdy` runs as root (`f_bavail` excludes them for other users).
- **Thresholds:** spec `paths: [{path, min_free, recommended_free, min_free_inodes, noexec: forbid, fstype_not: [nfs, cifs, fuse]}]`. Block if free < `min_free`. Warn if free < `recommended_free` (default `min_free` plus 20%). Block on a forbidden flag or fstype. Inodes are skipped when `f_files == 0` (btrfs and others); otherwise default `min_free_inodes: 100000`.
- **Fix:** "`{path}` is on `{mount}` with `{have}` free, `{min}` needed. Run `df -h {path}`. Grow the volume (`lvextend -r -L +{n}G {lv}`) or point the install at a larger disk. For `noexec`: `mount -o remount,exec {mount}` and remove `noexec` from `/etc/fstab`, or move the install path." The Docker `d_type` question moved to `host.container_runtime`.
- **Fixture:** `mountinfo` files (root xfs, separate `/var` ext4, `/tmp` tmpfs `noexec`, NFS home, a mount point with `\040` in it), `native/statvfs.json` keyed by path. Cases: plenty, tight, no inode accounting, missing parent, `noexec` temp dir, hung NFS (delay beyond the timeout), root-run note.

### host.memory (M1)
- **Measures:** total RAM, available RAM, swap total, used and limit, and the cgroup memory limit when `rdy` runs inside a container or slice (the report says "limited by cgroup, host has more").
- **Source:** L: `/proc/meminfo` (`MemTotal`, `MemAvailable`, `SwapTotal`, `SwapFree`; if `MemAvailable` is missing, as before kernel 3.14, use `MemFree + Buffers + Cached` and say "estimated"); the cgroup helper for the effective limit and `memory.swap.max`. M, W: `sysinfo` through `native`.
- **Needs:** none, timeout 2s.
- **Thresholds:** spec `min` (total), `min_available`, `swap: off|any` (default `any`), `band`. Total below `min` minus the nominal band: block. Inside the band: pass with a note. Available below `min_available` (default 50% of `min`): warn "the box is busy". `swap: off` with swap on: block (kubelet refuses to start with swap unless configured).
- **Fix:** "`{have}` RAM, `{min}` needed. Add RAM or pick a larger node class. A nominal 32 GiB machine shows about 31 GiB, so ask for a size class, not an exact number." Swap: "Run `swapoff -a` and comment out swap lines in `/etc/fstab`."
- **Fixture:** `meminfo` variants (32 GiB VM showing 31.3 GiB, 4 GB VM showing 3.8 GiB, 16 GiB, swap on, low available, no `MemAvailable`), cgroup v1 and v2 trees for a nested slice, with and without a limit.

### host.ports (M1)
- **Measures:** which required TCP and UDP ports are already bound and by which process; overlap of required fixed ports with the ephemeral range; ports reserved by the OS.
- **Source:** L: `/proc/net/tcp` and `tcp6` (state `0A` is LISTEN, the only TCP state counted), `/proc/net/udp` and `udp6` (bound UDP sockets show state `07`; every row with a non-zero local port counts as bound). Addresses are little-endian hex per 32-bit word (`0100007F` is 127.0.0.1, tcp6 has four words); a `[::]` listener is treated as covering IPv4 as well, and the evidence says so. Owner lookup is lazy: find conflicting inodes in `/proc/net` first, then walk `/proc/<pid>/fd` only until each inode is found, so thousands of processes do not burn the timeout. Process name: basename of `/proc/<pid>/cmdline` argv[0] first, then `/proc/<pid>/comm` (cut to 15 bytes) as a prefix match. `/proc/sys/net/ipv4/ip_local_port_range`. `/proc/net` is per network namespace: the evidence carries the netns (`read_link /proc/self/ns/net`) and warns "container view" when `host.os` says container. There is no bind fallback. If `/proc/net/*` is unreadable, the result is `partial` with owner unknown. M: `/usr/sbin/netstat -anv -p tcp` and `-p udp` (addresses print as `127.0.0.1.6443` and `*.6443`, the port is after the last dot; the `-v` PID column gives the owner). W: `%SystemRoot%\System32\NETSTAT.EXE -ano` (listening rows found by foreign address `0.0.0.0:0`, because the state word is localized; UDP rows have no state column) and `%SystemRoot%\System32\netsh.exe int ipv4 show excludedportrange protocol=tcp` (rows match `^\s*\d+\s+\d+\s*\*?\s*$`, headers are localized). `listeners` or `netstat2` may replace both parsers on macOS and Windows after a spike.
- **Needs:** wants Root, timeout 5s. Without root the owner of a port held by another user is `unknown`; the port is still reported as in use.
- **Thresholds:** spec `free: [80, 443, 6443, 10250]`, `udp_free: [...]`, `allow_owner: [acme-controller-manager]` (a previous install of the product itself is not a conflict), `bind: public|loopback` per port (default `public`). In use by another process: block. Required port inside the ephemeral range or a Windows excluded range: warn. Bound only to loopback while `bind: public`: warn.
- **Fix:** "Port `{p}` is held by `{proc}` (pid `{pid}`). Stop it (`systemctl stop {unit}`, the unit is read from `/proc/<pid>/cgroup`; the sentence is dropped when there is none) or change the product port in `{setting}`." Ephemeral overlap: "`echo 'net.ipv4.ip_local_reserved_ports = {port}' | sudo tee /etc/sysctl.d/90-acme-ports.conf && sudo sysctl --system`."
- **Fixture:** `/proc/net/tcp`, `tcp6`, `udp`, `udp6` snapshots; `/proc/<pid>/fd` symlinks (`socket:[8841]`) through `root.manifest.json`; a non-root view where fds are unreadable; netstat outputs for macOS (with `*.6443`) and Windows (with a UDP row and an excluded-range listing); cases: free, held by a named process, `comm` truncation, `[::]` listener, loopback only, container view.

### host.lsm (M1-late)
- **Measures:** SELinux mode (runtime and configured), AppArmor state and loaded profiles, recent denials naming watched contexts or programs.
- **Source:** L: SELinux `/sys/fs/selinux/enforce` (`1` enforcing, `0` permissive; absent means disabled, or "not visible" when `host.os` says container, because the path is often masked), `/etc/selinux/config` (`SELINUX=`), denials from the tail of `/var/log/audit/audit.log` (`type=AVC ... denied`, last 1 MiB, window from the `msg=audit(epoch.ms:id)` stamps; the evidence says "window truncated" when 1 MiB does not reach back to `denials_window`; systems without auditd keep AVCs in the journal, which M1 does not read). AppArmor `/sys/module/apparmor/parameters/enabled` (`Y`), profiles from `/sys/kernel/security/apparmor/profiles`. M, W: not applicable.
- **Needs:** wants Root, timeout 3s. Without root: modes are readable, the audit log and profile list are not, so denials are `not inspected` (partial).
- **Thresholds:** spec `selinux: {allow: [enforcing, permissive, disabled], denials_max: 0, denials_window: 24h, watch: [container_t, acme_t]}` and `apparmor: {allow: [...], require_profiles: [...]}`. A mode outside `allow`: block. Denials above `denials_max`: warn (block if the context is in `watch`). Default `allow` is all modes, so with no spec the check is informational.
- **Fix:** "SELinux is enforcing and denied `{n}` actions for `{ctx}`. Read them with `ausearch -m avc -ts recent`. Install the vendor policy module, or label the volume (`chcon -Rt container_file_t {path}` or the `:Z` mount option). Last resort: `setenforce 0` now and `SELINUX=permissive` in `/etc/selinux/config`."
- **Fixture:** `enforce` and `config` variants, synthetic `audit.log` excerpts, AppArmor files, a root-less run (audit log listed as `unreadable` in the manifest), a container with masked `/sys/fs/selinux`.

### host.security_agents (M1-late)
- **Measures:** whether a process from a known security-software category is running (EDR, antivirus, DLP, backup). It says "a process with this name is running", not "this product is installed".
- **Source:** L: `/proc/*/comm`. The kernel cuts it to 15 bytes, so a catalog name longer than that also matches a `comm` equal to its first 15 bytes. `cmdline` is never read: the read policy refuses it (ADR 0036). M, W: process names from `sysinfo` through `native`. Matches the embedded `agents.toml` (Appendix B). Directories, unit names, kernel modules and `systemextensionsctl` are M2; Windows WMI and Defender exclusions are M2 on a dedicated thread (the exclusions key is admin only, `SecurityCenter2` is empty on Server SKUs).
- **Needs:** wants Root, timeout 5s. Without root other users' processes are invisible, so absence is "not detected (limited view)".
- **Thresholds:** spec `forbid: [agent ids]`, `allow: [agent ids]`. Detected and not in `allow`: warn. In `forbid`: block. Evidence shows the process name, never the user or command line.
- **Fix (fixed neutral text):** "Detected `{display_name}` ({category}). Software in this category often inspects file opens and process launches. If the install is slow or fails, ask the security team to review exclusions for `{paths}`, then rerun." The catalog has no free-text risk note; `exclusion_docs_url` points to the vendor's own public page.
- **Fixture:** synthetic process lists (names only), `comm` truncation case. Each `agents.toml` entry has a unit test and a fixture. The seed list (10 to 15 entries, each with `source` URL and `checked_on`) is a deliverable of the ticket and needs the founder's approval before merge; product names live in `agents.toml`, not in prose.

### host.firewall (M1-late)
- **Measures:** which host firewall manager is active, its default policy, and whether the spec's inbound ports are allowed.
- **Source:** L: firewalld active if `/run/firewalld` exists, then `firewall-cmd --state` (exit 252 means not running) and `firewall-cmd --list-all --zone={zone}` where the zone is the one holding the default-route interface (`--get-active-zones`; the interface comes from `/proc/net/route`, then `/proc/net/ipv6_route`, lowest metric first; with no match and one active zone that zone is used and the evidence says so, with several the result is "unknown"). A port opened through a service name is resolved from `/etc/firewalld/services/<name>.xml`, then `/usr/lib/firewalld/services/<name>.xml` (the file in `/etc` replaces the packaged one; `<include>` is followed four levels; a missing service file is "unknown", never "closed"). Direct rules are read, as root only, from `/etc/firewalld/direct.xml` (any `<rule>` or `<passthrough>` makes every answer "unknown"; rules added at runtime with `firewall-cmd --direct` are not visible). A zone target of `ACCEPT` opens every port. ufw from `/etc/ufw/ufw.conf` (`ENABLED=yes`); `/etc/ufw/user.rules` is mode 640 root, and its `### tuple ###` comment lines are read in file order against `DEFAULT_INPUT_POLICY` in `/etc/default/ufw`. Raw `nft list ruleset` and `iptables -S` are M2. M, W: not applicable in M1 (target servers are Linux).
- **Needs:** wants Root, timeout 5s. Without root only the manager state is read (`firewall-cmd --state`, `ufw.conf`), the zone listing and `user.rules` are not tried, and each requested port is "unknown": "firewall active, rules not inspected", a warning with `partial.missing: [root]`. With no ports requested the check passes and names the active manager.
- **Thresholds:** spec `open_inbound: [6443, 10250]`. Verified closed: block. Active but not verifiable, or any rich rule, ipset or direct rule present (cannot be judged from `--list-all`): warn "unknown". Inactive: pass.
- **Fix:** "firewalld blocks `{port}/tcp` in zone `{zone}`. Run `firewall-cmd --permanent --zone={zone} --add-port={port}/tcp && firewall-cmd --reload`" or "`ufw allow {port}/tcp`".
- **Fixture:** `tests/fixtures/checks/host.firewall/`: firewalld `--list-all` recorded output (port open by number, open by service with an `/etc` override, closed in the default-route zone while another zone opens it, rich rule present, stopped daemon), service XML, `ufw.conf`, `user.rules` (allowed, closed, limited source), a root-less run for each manager. The spec parameter `open_inbound` and the registration in `HostFamily` follow in a spec ticket (M1-147 builds `rdy_checks_host::Firewall` from a list of ports).

### host.time_sync (M1-late)
- **Measures:** whether the clock is synchronized, by what, and the offset against a reference.
- **Source:** L: `adjtimex(2)` with `modes = 0` through `native` (read only; `STA_UNSYNC` and estimated error; `EPERM` inside a container with the default seccomp profile is `partial`, not an error); `timedatectl show -p NTPSynchronized -p NTP -p Timezone` (needs systemd 239; older systems fall back to `timedatectl status` and parse `NTP synchronized:`); `chronyc -n -c -t 3 tracking` (CSV). Offset: an in-process SNTP client over UDP to the servers in spec `ntp_servers` (random transmit timestamp that the reply must echo, mode 4 only, reject stratum 0 and 16, offset `((T2-T1)+(T3-T4))/2`). There are no default servers, because offline-first means no surprise traffic. With no `ntp_servers`, the result says "offset not measured". M, W: the sync-state sources are not applicable; the SNTP offset is OS independent.
- **Needs:** none, timeout 5s (SNTP 3s per server).
- **Thresholds:** spec `max_skew` (the block level, default 300s, because AWS signing, Kerberos and TLS validity fail near 5 minutes) and `recommended_skew` (the warn level, default 5s), `require_sync: true|false`. Not synchronized and `require_sync`: block.
- **Fix:** "Clock is `{off}` away from `{ref}` and not synchronized. Run `timedatectl set-ntp true`, or install chrony (`dnf install chrony && systemctl enable --now chronyd`, then `chronyc makestep`). On VMs also enable host time sync (VMware Tools, Hyper-V integration services)."
- **Fixture:** `native/adjtimex.json`, `timedatectl show` and `status` outputs, `chronyc -c tracking` output, a hex SNTP reply with a known offset and a reply that fails the echo check.

### host.cpu (M1)
- **Measures:** logical and physical cores (respecting cgroup quota and affinity), architecture, model, feature flags and levels, whether it is a VM, and whether `rdy` itself runs under Rosetta.
- **Source:** all OS: `std::thread::available_parallelism` and `std::is_x86_feature_detected!` or `std::arch::is_aarch64_feature_detected!` through `native` (fixed table of flag names, since the macros need literals). L: `/proc/cpuinfo` for other flag names, `hypervisor` flag; on aarch64 VMs `/sys/class/dmi/id/product_name` and `/sys/hypervisor/type`; the cgroup helper explains a quota ("quota 200000/100000 means 2 cores"); `/sys/devices/system/cpu/cpu*/topology/{core_id,physical_package_id}`. M: `sysinfo` counts, `/usr/sbin/sysctl -n sysctl.proc_translated hw.optional.arm64` (the first key is missing on Intel Macs and exits 1: treat as 0). W: `sysinfo` counts. Flags also compute `x86-64-v2` and `x86-64-v3`.
- **Needs:** none, timeout 2s.
- **Thresholds:** spec `min_cores`, `recommended_cores`, `arch: [x86_64, aarch64]` (also accepts `amd64` and `arm64`), `flags: [avx2, bmi2, x86-64-v3]`. Below `min_cores`, wrong arch or a missing flag: block. Below `recommended_cores`: warn. Running translated: warn.
- **Fix:** "`{n}` vCPU, `{min}` needed. Resize the instance. Missing `avx2`: set the VM CPU model to host passthrough (libvirt `<cpu mode='host-passthrough'/>`), turn off VMware EVC masking, or on Hyper-V run `Set-VMProcessor -VMName {vm} -CompatibilityForMigrationEnabled $false` on the hypervisor."
- **Fixture:** `/proc/cpuinfo` with and without `avx2`, with `hypervisor`, arm `Features`; cgroup `cpu.max` quota and the v1 `cpu.cfs_quota_us` form; macOS sysctl outputs including `proc_translated=1`; `native/cpu_flags.json`.

### host.sysctl (M1-late)
- **Measures:** kernel parameters and file limits against the spec, and whether a live value survives a reboot.
- **Source:** L: `/proc/sys/<name with dots as slashes>` (the spec may use `/` as the separator, for names such as `net.ipv4.conf.eth0.100.rp_filter`). Persistence: files in `/etc/sysctl.d`, `/run/sysctl.d`, `/usr/local/lib/sysctl.d`, `/usr/lib/sysctl.d`, `/lib/sysctl.d`; a file name in a higher-priority directory masks the same name below; the union is applied in lexical order of base name; `/etc/sysctl.conf` is applied last; `#` and `;` comments, `-key` and spaces around `=` are handled. Limits: `DefaultLimitNOFILE` from `/etc/systemd/system.conf` and `system.conf.d` (this is the service-relevant one), `/proc/sys/fs/nr_open`, `/proc/sys/fs/file-max`; `rdy`'s own `RLIMIT_NOFILE` is labelled "shell limit". M, W: not applicable.
- **Needs:** none, timeout 2s.
- **Thresholds:** no built-in defaults, the spec lists them: `expect: {vm.max_map_count: ">=262144", net.ipv4.ip_forward: "1", fs.inotify.max_user_watches: ">=524288"}`, `limits: {nofile: ">=65536"}`. Wrong live value: block. Right live value but not persisted: warn.
- **Fix:** "`vm.max_map_count` is `{have}`, need `262144`. Run `sysctl -w vm.max_map_count=262144` and persist it: `echo 'vm.max_map_count = 262144' | sudo tee /etc/sysctl.d/90-acme.conf && sudo sysctl --system` (`sysctl -p` does not read `sysctl.d`). - **Fixture:** fake `/proc/sys` tree, `sysctl.d` files in two directories with a masked name, `system.conf`.

### host.container_runtime (M1-late)

### host.os (M1)
- **Measures:** distro, version, architecture, init system, container or WSL, FIPS mode.
- **Source:** L: `/etc/os-release` (fallback `/usr/lib/os-release`: `ID`, `ID_LIKE`, `VERSION_ID`), `uname` through `native`, `/run/systemd/system`, `/.dockerenv`, `/run/.containerenv` (Podman), env `KUBERNETES_SERVICE_HOST`, `/proc/sys/kernel/osrelease` (contains `microsoft` under WSL), `/proc/sys/crypto/fips_enabled`. ## 3. Network family (`rdy-checks-net`)

All network checks run in process on every OS, so the Source line is the same for L, M and W unless stated. They probe from the machine running `rdy`, which is not a cluster node (see `k8s.egress_probe` in section 9).

Shared stack, all through the probe facade: `tokio::net::TcpStream` opened by the facade with per-stage timeouts, our own `CONNECT` (about 40 lines, status line parsed with `httparse`, response header capped at 16 KiB), `tokio-rustls` built with `builder_with_provider(ring)` (not the process default, so unit tests do not need `rdy-cli`'s startup), `hyper::client::conn::http1` for requests, `rustls-native-certs` (loaded once in `spawn_blocking` and cached; the result carries per-cert errors, surface their count) and `webpki-roots` as the public baseline, `x509-parser` without its `verify` feature, `hickory-resolver` with `default-features = false` (only the tokio and system-config features; the default DoT and DoH features pull `aws-lc-rs` and trip the ban in ADR 0009). No `reqwest` in any check. Requests send `Accept-Encoding: identity` and offer ALPN `http/1.1` only (the negotiated value is reported). Redirects are not followed.

| Order | Id | Tier | Privilege | One line |
| --- | --- | --- | --- | --- |
| 1 | `net.egress` | M1 | none | TCP, TLS and HTTP to required endpoints, direct and via proxy |
| 2 | `net.proxy` | M1 | none | The proxy settings the product would really see |
| 3 | `net.tls_intercept` | M1 | none | Is a middlebox re-signing TLS |
| 4 | `net.dns` | M1-late | none | Names resolve, by the system and by each nameserver |
| 5 | `net.registry` | M1-late | none | OCI registry API, token host and blob host |
| 6 | `net.mtu` | M1-late | none | Interface MTU and overlay headroom |
| 7 | `net.bandwidth` | M1-late | none | Download throughput sample |

### net.egress (M1)
- **Measures:** for each endpoint, per stage: DNS, TCP connect, TLS handshake (chain, SNI, ALPN), optional HTTP request; direct and through the proxy; latency; the `Date` header skew (evidence only, no other check reads it); the `Location` host of any redirect.
- **Source:** facade `lookup` then `connect` per resolved address (cap 4, IPv6 first with a 250 ms stagger, 3s per attempt so the total stays under 10s; the report names which family failed, since a dead AAAA record is a top cause of "hangs"). Endpoint forms: `host:port` or URL. TLS is attempted when the port is 443, the scheme is `https`, or the spec sets `tls: true`; otherwise TCP connect only. Proxy resolution comes from `net.proxy`. `https` and `host:port` endpoints use `CONNECT` (Basic auth only, from the proxy URL, userinfo percent-decoded and the header never logged); `http://` endpoints through a proxy use the absolute-form request, because Squid's default denies `CONNECT` to ports other than 443 and would give a false `proxy_403`. 407 with `Negotiate` or `NTLM` is reported, not attempted. Trust store: system, with the bundled public roots as fallback; the evidence says which. The peer policy of ADR 0009 applies: link-local and metadata addresses are refused even when listed, and only spec-listed endpoints are contacted.
- **Needs:** needs Network, timeout 10s per endpoint for connect plus TLS, 15s for HTTP, 8 endpoints in parallel, 60s total.
- **Thresholds:** spec `endpoints: [str | {url, expect_status: [200, 401], optional, method: HEAD|GET, via_proxy, tls}]`, `via_proxy: auto|direct|proxy_only` (`auto` tries what the product would do and, if that fails but the other path works, says so), `trust: system|bundled`, `max_latency` (warn above 2s connect). An unreachable endpoint: the spec severity (default block). An `optional` endpoint: warn. Date skew above 300s: warn. Failure classes, each with its own text: `dns`, `refused`, `blackhole` (SYN unanswered), `tls_unknown_issuer` (evidence carries issuer and chain depth, and points to `net.tls_intercept`), `clock_or_expiry` (certificate expired or not yet valid; never reported as interception), `tls_alert`, `reset_after_hello` (SNI filtering, or a legacy server that speaks only TLS 1.0 and 1.1; the hint prints `openssl s_client -connect {host}:{port} -servername {host}`), `proxy_407`, `proxy_403` (CONNECT denied by allow-list), `refused_by_policy`, `http_status`.
- **Fix:** per class. Blackhole: "No reply to SYN from `{ip}:{port}` in 3s, a firewall is dropping it. Ask the network team to allow tcp/`{port}` to `{host}` from `{source_ip}`." Proxy 403: "The proxy refused CONNECT to `{host}:{port}`. Ask the proxy team to add it to the allow list." Direct fails, proxy works: "Set `HTTPS_PROXY={proxy}` for the product service, not only your shell." Redirect: "`{host}` redirects to `{other}`. Add `{other}:443` to the endpoints to test it."
- **Fixture:** a scripted connector (`net.json`) for unit tests: `refused`, `blackhole` (a listener that never accepts does not produce a blackhole on loopback, because the kernel completes the handshake until the backlog fills, so blackhole exists only as a scripted outcome), `reset`. Loopback servers from `rdy_engine::testing::loopback` (ADR 0035) for integration: TLS server with a generated test CA (`rcgen` with `default-features = false` and the ring feature), CONNECT proxy with modes `ok`, `403`, `407-basic`, `407-negotiate`, a server that reads the ClientHello and closes with linger 0 (`socket2`, since the tokio method is deprecated), a `302` to a second host, a dual-stack case with a dead IPv6 address, an expired certificate with a pinned clock. Planted-secret test: proxy userinfo and a query-string token never reach the result.

### net.proxy (M1)
- **Measures:** the proxy configuration in effect, where each setting comes from, whether daemons have it too, whether `NO_PROXY` covers internal destinations, whether the proxy is reachable.
- **Source:** L: environment through the facade (`HTTPS_PROXY`, `https_proxy`, `HTTP_PROXY`, `ALL_PROXY`, `NO_PROXY`, `no_proxy`; flag upper and lower case that disagree, and note that curl ignores upper-case `HTTP_PROXY`); drop-ins for `docker`, `containerd` and `kubelet` units under `/etc/systemd/system/*.service.d/*.conf`; later sources (after the first two, and first to cut): `/etc/environment`, `/etc/profile.d/*.sh`, `/etc/apt/apt.conf.d/*`, `/etc/dnf/dnf.conf` and `/etc/yum.conf` (`proxy=`), `/etc/systemd/system.conf` (`DefaultEnvironment`), `EnvironmentFile=` targets such as `/etc/sysconfig/docker`, RKE2 and K3s `*.env` files, and `~/.docker/config.json` read into a struct holding only `proxies` (the `auths` key never reaches memory as a loggable string). M: `/usr/sbin/scutil --proxy` (a text dump: `HTTPSEnable`, `HTTPSProxy`, `HTTPSPort`, `ProxyAutoConfigURLString`, `ExceptionsList`). W: registry `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` (`ProxyEnable`, `ProxyServer`, `ProxyOverride`, `AutoConfigURL`, auto-detect flag) and the WinHTTP blob `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Internet Settings\Connections\WinHttpSettings`, shipped first as `partial`; the evidence says that the per-user setting does not apply to a service running as SYSTEM, the WinHTTP machine setting does. **PAC and WPAD are detected, never fetched or evaluated** (ADR 0009): the URL is recorded without query or userinfo.
- **Needs:** none, timeout 5s. `NO_PROXY` matching uses one documented rule set (leading dot, `*`, CIDR, ports, IPv6 literals), implemented with `hyper_util`'s proxy matcher if the pinned version exposes it, otherwise a table-tested matcher. `socks5://`, `socks5h://` and `https://` proxy schemes are reported as "not supported by rdy in M1" and not probed.
- **Thresholds:** spec `required_no_proxy: [".svc", ".cluster.local", "10.0.0.0/8", "169.254.169.254"]`, `daemons_need_proxy: true|false`. Proxy TCP unreachable: block. Required `NO_PROXY` entry missing: warn (block if the spec says so). Proxy set for the shell but not for docker, containerd or kubelet while they are present: warn (block with `daemons_need_proxy`). PAC or WPAD in use: warn "rdy cannot evaluate PAC, set `HTTPS_PROXY` explicitly or use `via_proxy` in the spec".
- **Fix:** "Docker does not see the proxy. Create `/etc/systemd/system/docker.service.d/http-proxy.conf` with `[Service]` and `Environment=\"HTTP_PROXY={proxy}\" \"HTTPS_PROXY={proxy}\" \"NO_PROXY={no_proxy}\"`, then `systemctl daemon-reload && systemctl restart docker`."
- **Fixture:** environment maps, fake `/etc` trees with and without drop-ins, a `docker/config.json` with a planted `auths` secret, `scutil --proxy` output, registry JSON including a WinHTTP blob, a PAC-configured case (no fetch happens; the connector has no route for it).

### net.tls_intercept (M1)
- **Measures:** whether TLS to each host is terminated by a middlebox, who issued the presented chain, and whether that issuer is trusted on this machine.
- **Source:** one handshake per host (hosts default to the `net.egress` endpoints) with a recording `ServerCertVerifier` installed through `ClientConfig::builder_with_provider(ring).dangerous()`. Inside `verify_server_cert` it runs two real `WebPkiServerVerifier`s (one from `webpki-roots`, one from `rustls-native-certs`), records `end_entity`, `intermediates` and each verdict, then returns Ok so the handshake completes. Signature checks delegate to the provider. One handshake yields all classes, then `close_notify` and zero application bytes. `UnixTime` is injectable. Classes: (a) validates against the bundled public roots: no interception; (b) validates only against the OS store: "chain is trusted by this machine only, issuer `{issuer}`" (the Windows and macOS stores carry roots Mozilla does not, so this is not stated as an inspection proxy); (c) validates nowhere: the issuer's CA is not installed, product clients will fail; `clock_or_expiry` for `Expired`, `NotValidYet` and `ExpiredContext`, reported separately and never as interception; "no OS trust store found" when the store is empty (scratch or Alpine without `ca-certificates`). Evidence: issuer and subject names, chain depth, SHA-256 of the root, validity dates, SAN match; where the root lives (Linux: the bundle file; elsewhere "System keychain" or "Windows Root store"). It also reports the other trust stores on the box (Java `cacerts` under `/usr/lib/jvm/*/lib/security/`, `SSL_CERT_FILE`, `NODE_EXTRA_CA_CERTS`). The verifier is private to this probe (ADR 0009 item 5). `reqwest`'s `tls_info` exposes only the leaf and only after a successful verification, which is the case where interception is invisible; that is why the raw handshake is used.
- **Needs:** needs Network, same limits as `net.egress`.
- **Thresholds:** spec `hosts`, `expected_issuer: <regex>`, `pin_sha256: [..]`, `forbid_interception: true|false`. (a): pass. (b): warn, block if `forbid_interception` (vendors with certificate pinning or mutual TLS cannot cross an inspecting proxy). (c): block. `clock_or_expiry`: block with its own text and a pointer to `host.time_sync`. Issuer not matching `expected_issuer`: block.
- **Fix:** "`{host}` is presented with a chain from `{issuer}` that this machine only partly trusts. Either ask the network team to bypass inspection for `{host}`, or install that CA. Debian and Ubuntu: copy it to `/usr/local/share/ca-certificates/acme-inspection.crt` (the name must end in `.crt`), run `update-ca-certificates`. RHEL: copy to `/etc/pki/ca-trust/source/anchors/`, run `update-ca-trust`. SUSE: `/usr/share/pki/trust/anchors/` then `update-ca-certificates`. Alpine: `/usr/local/share/ca-certificates/` then `update-ca-certificates`. Java: `keytool -importcert -cacerts -alias acme-inspection -file ca.crt`. Container images and Java do not read the host store."
- **Fixture:** DER chains generated at test time with `rcgen`: public-style, private-CA with its root in a fake system store directory, unknown CA, expired leaf with a pinned clock. Golden values use placeholders. Unit test: the probe writes zero application bytes. Load-once test for the native store cache.

### net.dns (M1-late)
- **Measures:** whether required names resolve the way the product's own resolver would resolve them, whether each configured nameserver agrees, latency, and the resolver settings that cause trouble.
- **Source:** L: the system answer from `/usr/bin/getent ahosts <name>` through `exec` (glibc behaviour: `nsswitch.conf`, mDNS, sssd, which a static musl resolver does not honour; this refines ADR 0006 item 5 and needs its amendment). Uses `ahosts` so AAAA-only names are seen, dedupes the three rows per address, exit code 2 means not found and any other non-zero code is a tool error. The name is validated against `^[A-Za-z0-9._-]+$`, must not start with `-`, and follows `--`. If `getent` is missing (scratch containers, Alpine) the fallback is `hickory-resolver` from `/etc/resolv.conf` and `/etc/hosts`, and the evidence says so. Direct lookups with `hickory-resolver` against each nameserver in `/etc/resolv.conf`, or `/run/systemd/resolve/resolv.conf` when the first is the `127.0.0.53` stub; `nsswitch.conf` `hosts:` line (flag `mdns4_minimal [NOTFOUND=return]` before `dns`). A 5s kill of `getent` can fire before the resolver's own `timeout x attempts x servers`; the result is `Timeout` with the `options timeout/attempts` values in the evidence. M: facade `lookup` (`getaddrinfo`), nameservers from `/usr/sbin/scutil --dns`. W: facade `lookup`, nameservers from registry `HKLM\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\*` (`NameServer`, `DhcpNameServer`).
- **Needs:** needs Command(getent) on Linux or falls back, timeout 5s per lookup, 8 names in parallel.
- **Thresholds:** spec `names: [str | {name, expect_in: ["10.0.0.0/8"], expect_public: true}]`, `max_ms` (warn above 500). System lookup fails: block. Direct and system answers differ (split horizon): warn. A nameserver times out while another answers: warn "slow first hop adds a timeout to every lookup". `expect_in` not satisfied: block.
- **Fix:** "`{name}` does not resolve through `{resolver}`: nameserver `{ip}` answered `{rcode}`. Ask the DNS team for a conditional forwarder for `{zone}`, or add a temporary line to `/etc/hosts`."
- **Fixture:** `resolv.conf` (stub and real), `nsswitch.conf` (with `sss` and mdns), recorded `getent` output (found, not found exit 2, timeout, dual-stack rows), an in-process scripted DNS server (`hickory-server` with default features off, dev dependency) with zones for NXDOMAIN, SERVFAIL, delayed and split answers. Exit test includes `cargo deny check`.

### net.registry (M1-late)
- **Measures:** an OCI registry works end to end: API ping, auth token host, manifest, and the host that serves layer blobs.
- **Source:** `GET https://<host>/v2/` (200 or 401); parse `WWW-Authenticate: Bearer realm=...,service=...`. Hosts the spec does not list are not contacted (ADR 0009): the token realm host and any blob redirect host are recorded, and the text says which to add under `hosts`. For listed public images: anonymous token, then on `docker.io` a manifest `HEAD` (does not count against the anonymous pull limit), on other registries a manifest `GET` with the OCI and Docker v2 `Accept` types (a multi-arch index is resolved to the first matching platform), then `HEAD` on the config blob, which is served from the same blob host as the layers. Never reads or sends credentials. Reports mirror settings found in `/etc/docker/daemon.json` and `/etc/containerd/certs.d/*`, and Docker Hub rate-limit headers when present.
- **Needs:** needs Network, 15s per step.
- **Thresholds:** spec `registries: [host | {host, hosts: [token and blob hosts], images: [repo:tag], optional}]`. `/v2/` fails: block. A listed token or blob host unreachable: block (the classic: manifests work, layers hang). A discovered host that is not listed: warn "not tested, add it". Private image answers 401: warn "needs credentials, not verifiable". Rate limit remaining below 10: warn.
- **Fix:** "`{registry}` answers but its blob store `{cdn}` is blocked, so pulls fail on layers with timeouts or `unexpected EOF`. Allow `{cdn}:443`."
- **Fixture:** loopback registry mock: 401 with a Bearer header, token endpoint, manifest index and single manifest, config blob `307` to a second loopback port that is open or closed.

### net.mtu (M1-late)
- **Measures:** MTU of the default-route interface and other up interfaces, VPN and tunnel interfaces, and headroom for an overlay network. It does not measure path MTU (`net.pmtu`, reserved).
- **Source:** L: `/sys/class/net/<if>/{mtu,operstate,type}`, default route from `/proc/net/route` and `/proc/net/ipv6_route`. M, W: `sysinfo::Networks` MTU through `native` (confirm `NetworkData::mtu()` at the pinned version; no `ifconfig`, no PowerShell).
- **Needs:** none, timeout 3s.
- **Thresholds:** spec `min_mtu`, `overlay: vxlan|geneve|wireguard|ipip`, `underlay: ipv4|ipv6`. Overhead values come from published tables, cited in code: IPIP 20; VXLAN 50 (IPv4 underlay) or 70 (IPv6); WireGuard 60 or 80; Geneve 50 plus options (OVN-Kubernetes reserves 100). Interface MTU minus overlay overhead below `min_mtu`: block. Default interface MTU below `min_mtu`, or below 1400 with no spec: warn. MTU above 1500 (9001 is the default on EC2): informational unless the spec sets `overlay` or an expected MTU, then warn "traffic leaving the network clamps to 1500, make sure ICMP 'fragmentation needed' is not filtered".
- **Fix:** "`eth0` has MTU 1450 and VXLAN needs 50 bytes, so the pod network must use 1400 or less. Set the CNI MTU to `{n}`."
- **Fixture:** `/sys/class/net` trees, `/proc/net/route`, `native/sysinfo_networks.json`.

### net.bandwidth (M1-late)
- **Measures:** single-stream download rate and time to first byte from a vendor-chosen URL (a lower bound).
- **Source:** facade GET through the resolved proxy with `Range: bytes=0-{bytes-1}` and `Accept-Encoding: identity`; stream and discard, never buffer; stopped at `bytes` (default 10 MiB, max 100 MiB) or 10s. A response shorter than 1 MiB reports "sample too small", not a rate. The rate is measured after the first 10% to avoid slow-start bias. No upload in any case. No default URL. The URL goes into evidence as `scheme://host:port/path` only (presigned URLs).
- **Needs:** needs Network, 15s.
- **Thresholds:** spec `url`, `bytes`, `min_mbps` (block), `recommended_mbps` (warn). No thresholds in the spec: informational.
- **Fix:** "`{x}` Mbit/s to `{host}` (single stream, so a lower bound). Pulling `{size}` takes about `{t}`. Use a registry mirror in this region or the offline bundle."
- **Fixture:** rate maths behind an injected clock and unit tested with fixed `(bytes, instant)` samples; one loose loopback smoke test (within a factor of 2), because shared macOS and Windows runners make a tight tolerance flaky.

## 4. Kubernetes family (`rdy-checks-k8s`)

Client: `kube` with rustls (ADR 0010). Kubeconfig order is `--kubeconfig`, `KUBECONFIG` (several paths allowed, separated by the OS list separator), `~/.kube/config`, then in-cluster; the report says which was used. Flags are `--context` and `--namespace` (matches `kubectl`; ADR 0010 says `--kube-context`, cli-ux to choose). Requests are GET (including list), plus the review kinds, enforced by the guard layer in the facade (02): `SelfSubjectAccessReview`, `SelfSubjectRulesReview`, `SelfSubjectReview`, and, only when the spec and the user flag both turn it on, one `POST /api/v1/namespaces/{ns}/pods?dryRun=All`. Lists use `limit=500` pagination with a 5000 object cap per list; a capped list marks the dependent part "not evaluated"; `410 Gone` on an expired continue token restarts once, then marks the check partial. Every k8s check except `k8s.access` needs `KubeContext` (a need, not a check dependency, per 02). Exec credential plugins named in the kubeconfig (for example `aws`, `gke-gcloud-auth-plugin`, `kubelogin`) are run by `kube`; the report header says "this kubeconfig runs `{cmd}`", a plugin `command` that is a relative path not on `PATH` is refused, and the `--kubeconfig` help text warns that a kubeconfig received from someone else can execute code.

**Proxy.** `kube` takes a proxy only from the kubeconfig `proxy-url` (with the proxy cargo feature on) and ignores `HTTPS_PROXY`, so `kubectl` can work while `rdy` times out. `k8s.access` resolves the proxy as `net.proxy` does (kubeconfig `proxy-url` first, then `HTTPS_PROXY` with `NO_PROXY` applied to the API host), sets it on the client, and reports which rule applied. ADR 0010 needs the proxy feature (see ADR list).

**Spec block.** A family-level block, so checks do not repeat fields:

```yaml
k8s:
  context_pattern: "^acme-prod-"
  server_pattern: "^https://.*\\.acme\\.example"
  namespace: acme-system
  service_account: acme-controller   # used in SCC and RBAC fix text
```

**Cluster facts.** Version, discovery documents, the Node list and the target `Namespace` are read by many checks. The k8s family fetches them once into a cached `ClusterFacts` (held in the family, per 02), records which list calls were forbidden, and checks use that. A first batch of read `SelfSubjectAccessReview`s (nodes, pods, storageclasses, csidrivers, csinodes, namespaces, webhook configurations, CRDs) tells later checks which calls to skip, which removes noisy 403s from the audit log and yields the exact "grant `list nodes`" text in one place. If the review itself is refused, fall back to the 403 `Status` message.

**Not evaluated.** Each partial result lists `not_evaluated: [{what, why, grant}]` so the HTML report can render it. Acceptance test: an identity that can only `get namespaces` produces a report where every check is partial or skipped and none is `block` on data it could not read.

**Fixtures for all of them:** recorded API responses served by a `tower` mock handed to `kube::Client::new`, with the guard layer in front, so no sockets and no cluster are needed. The mock models paging (`limit`, `continue`, `410 Gone`), field and label selectors (or one recorded file per full query string), legacy discovery documents (`/api` and `/apis`; aggregated discovery is a different document selected by `Accept` and is not recorded), and review answers from a table. Per-distro sets under `tests/fixtures/k8s/distros/{eks,gke,aks,openshift,k3s,rke2,kind}/` hold `version.json`, `nodes.json` (allocatable shapes, `providerID`, labels), `storageclasses.json`, `csidrivers.json`, `csinodes.json`, `ingressclasses.json` and a `Namespace` with the distro's PSA labels. `scripts/record-k8s-fixture.sh` uses a `jq` allow-list that drops `metadata.managedFields`, `last-applied-configuration` and node `status.images`, and rewrites provider ids, instance ids, ARNs and internal DNS names to acme values. One CI job runs against `kind` (oldest and newest supported minors) with a `restricted` PSA namespace and the review round trips, because only a real API server proves serialisation and review semantics.

### k8s.access (M1)
- **Measures:** kubeconfig found and which source, current context, API server reachable, who the credentials belong to, server certificate verified, credential lifetime, latency, and whether a proxy sits in the path.
- **Source:** the client module of `rdy-checks-k8s` (kubeconfig first, in-cluster as fallback; never `Config::infer`, ADR 0031); `GET /version`, then `SelfSubjectReview` (`authentication.k8s.io/v1`, GA 1.28; on older servers one cheap `SelfSubjectAccessReview` and the user is shown as not verified), because `/version`, `/api` and `/readyz` are open to anonymous callers and prove nothing about the credentials. Prints user and groups; warns on `system:anonymous`. Discovery calls named exactly: `/api` (core versions) and `/apis` (groups). Expiry is read only for static JWT tokens and client certificates; for exec plugins the evidence says "short-lived, refreshed by `{binary}`" with no expiry warning, and in-cluster tokens are skipped. A plugin that needs an interactive login (device code, SSO) is not killed: kube runs it, rdy cannot stop the process, and it may outlive the timeout (ADR 0031 decision 7, a documented residual; M1-107 proves rdy still exits). The check times out and is reported as "credential plugin `{binary}` did not answer in time, it may need an interactive login". Without a terminal on stdin and stderr the plugin runs non-interactively (ADR 0031 decision 8), so a device-code login fails fast instead of waiting. The server host is recorded without userinfo, never a token. Rancher kubeconfigs keep their URL path prefix.
- **Needs:** KubeContext (itself the probe outcome), timeout 10s.
- **Thresholds:** spec `context_pattern`, `server_pattern`, `max_latency` (warn above 2s for `/version`). No kubeconfig, unreachable, 401 or 403: block. `insecure-skip-tls-verify: true`: warn. A static credential expiring in under 7 days: warn. Anonymous: warn. Context or server not matching its pattern: block.
- **Fix, by cause.** Certificate: "`invalid peer certificate: UnknownIssuer` (kubectl says `x509: certificate signed by unknown authority`): the kubeconfig CA does not match, or a proxy re-signs TLS (run `net.tls_intercept`)." With no CA in the kubeconfig the cause is the same word but the hint differs: "the kubeconfig names no certificate authority, so rdy trusts only its bundled public roots, not this machine's store (kubectl uses it): pass a copy with `certificate-authority` set" (ADR 0031 decision 9). Expired credentials: EKS `aws eks update-kubeconfig --name {c} --region {r}`, GKE `gcloud container clusters get-credentials {c} --location {loc}` (and `gke-gcloud-auth-plugin` on `PATH`), AKS `az aks get-credentials -g {rg} -n {c}` then `kubelogin convert-kubeconfig -l azurecli`, OpenShift `oc login {server}`; expired AWS SSO: `aws sso login --profile {p}`. No reply or refused: "No reply from `{server}`. The API endpoint is private or limited to allowed networks. EKS: check `endpointPublicAccess` and `publicAccessCidrs`. GKE: master authorized networks. AKS: `--api-server-authorized-ip-ranges`. Run from a host inside the network." EKS `Unauthorized` after a good token: "The IAM principal is not mapped. `aws eks create-access-entry --cluster-name {c} --principal-arn {arn}` then `aws eks associate-access-policy ...`, or edit `aws-auth` on older clusters; only the cluster creator is admin by default." k3s or RKE2 on the same host: "The kubeconfig is root-only at `/etc/rancher/k3s/k3s.yaml`. Copy it to `~/.kube/config` and `chmod 600` instead of running `rdy` as root."
- **Fixture:** synthetic kubeconfigs (token, client cert, exec plugin, no file, `proxy-url`, env-only proxy, Rancher path prefix, multi-path `KUBECONFIG`), mock responses: `/version`, 401 and 403 `Status` bodies, TLS failure, slow reply, an anonymous kubeconfig, plugin failures.

### k8s.storageclass (M1)
- **Measures:** a usable default `StorageClass`, the named class if the spec names one, that a driver is registered for the class, binding mode, expansion, reclaim policy, and whether the class can serve the required access modes.
- **Source:** `storage.k8s.io/v1` `StorageClass` list (default marker `storageclass.kubernetes.io/is-default-class`, legacy `storageclass.beta.kubernetes.io/is-default-class`). The provisioner name is normalised: in-tree names map to their CSI driver (`kubernetes.io/aws-ebs` to `ebs.csi.aws.com`, `kubernetes.io/gce-pd` to `pd.csi.storage.gke.io`, `kubernetes.io/azure-disk` to `disk.csi.azure.com`, `kubernetes.io/azure-file` to `file.csi.azure.com`, `kubernetes.io/cinder` to `cinder.csi.openstack.org`, `kubernetes.io/vsphere-volume` to `csi.vsphere.vmware.com`), because on EKS the default class is `gp2` on `kubernetes.io/aws-ebs`, served only through CSI migration, and with no EBS CSI add-on every PVC stays Pending. Driver evidence, strongest first: `CSINode` `spec.drivers[].name` on at least one schedulable node (`storage.k8s.io/v1`), then a `CSIDriver` object (optional for a driver, so absence alone proves nothing). Classes on `rancher.io/local-path`, `kubernetes.io/no-provisioner` or a provisioner missing from `provisioners.toml` are "not CSI or unknown, driver not verified" and never block on driver grounds. Access modes cannot be read from a class, so they come from `provisioners.toml` (Appendix B; ceph provisioners match by suffix, so the OpenShift Data Foundation prefix works). If listing is forbidden, GET by name when the spec names a class, else partial. Evidence of broken provisioning that needs no canary: Pending PVCs older than 5 minutes in the target namespace and their Event reasons (`ProvisioningFailed`, `WaitForFirstConsumer`). No canary PVC is created. Zone count comes from `ClusterFacts`; absent zone labels mean "unknown", not one zone.
- **Needs:** needs KubeContext, wants list on storageclasses, csidrivers, csinodes, timeout 30s.
- **Thresholds:** spec `class`, `access_modes: [ReadWriteOnce, ReadWriteMany, ReadWriteOncePod]`, `binding: WaitForFirstConsumer`, `expansion: true`, `reclaim_policy: Retain|Delete` (warn on mismatch; Delete is a data-loss trap for data stores). No default and no named class: block. Named class missing: block. Required access mode unsupported: block (the plan example sets `severity: warn`). Normalised provisioner with no `CSINode` registration and no `CSIDriver`: block. `CSIDriver` exists but no `CSINode` lists it: warn "driver object found, no node has registered it, the node plugin may be down". `CSINode` list forbidden: use `CSIDriver` only, partial. More than one default: block below 1.26 (PVC creation fails), warn from 1.26 (the newest is used). `Immediate` binding on a zonal provisioner in a multi-zone cluster: warn. Expansion wanted but off: warn.
- **Fix:** "No EBS CSI driver is registered, so PVCs on `{class}` stay Pending. Install it with a role: `eksctl create addon --cluster {c} --name aws-ebs-csi-driver --service-account-role-arn {role_arn}`. The role needs the `AmazonEBSCSIDriverPolicy` managed policy and a trust relationship for the add-on service account (IRSA or EKS Pod Identity)." Class to select by distribution: GKE `standard-rwo`, AKS `managed-csi`, OpenShift `gp3-csi`. No default: "Mark one: `kubectl patch storageclass {name} -p '{\"metadata\":{\"annotations\":{\"storageclass.kubernetes.io/is-default-class\":\"true\"}}}'`."
- **Fixture:** `StorageClass` lists: none, one non-default, two defaults (server 1.25 and 1.28), EKS `gp2` with no CSI add-on (block), EKS with the add-on, k3s `local-path` (pass with "driver not verified"), `Immediate` zonal, `no-provisioner`, unknown provisioner, OpenShift Data Foundation prefix; `CSIDriver` and `CSINode` lists with and without the driver; Pending PVCs with Events.

### k8s.rbac (M1)
- **Measures:** whether the identity in the kubeconfig can do each thing the installer does, and who that identity is.
- **Source:** `SelfSubjectReview` for user and groups; `SelfSubjectAccessReview` per spec item (create only, nothing stored, up to 100 per run, 8 at a time). Item shape `{verb, group, resource, subresource?, namespace?, name?}` or `nonResourceAttributes {path, verb}` (for `/metrics` or `/healthz`). `SelfSubjectRulesReview` is used only to print what the identity can do in the target namespace when something is denied. Spec `as:` (for example `system:serviceaccount:{ns}:{sa}`) sends `Impersonate-User` when the user holds `impersonate`, otherwise "not evaluated". When the spec creates `ClusterRole` or `ClusterRoleBinding` objects, `escalate` and `bind` probes are added. The report states that each item is one audit-log entry, up to 100; the calls are read-only but visible.
- **Needs:** needs KubeContext, timeout 30s.
- **Thresholds:** spec `can: [...]`. Any item denied: block, listed with the reviewer's `reason`, saying which of `denied: true` (explicit deny, for example a webhook authorizer) or plain not-allowed it was. Denied `escalate` or `bind`: warn "cannot prove the identity may grant `{role}`; it passes if the identity already holds those rules" (block only when the spec supplies the granted rule set and the identity lacks one). `evaluationError` with `allowed: false`: warn.
- **Fix:** "`{user}` (groups `{groups}`) cannot `{verb}` `{resource}` in `{ns}`. Ask the cluster admin to bind the vendor installer role to this identity: `kubectl apply -f {role_url}` and a binding for `{user}` or one of its groups. On a throwaway test cluster only, `cluster-admin` works."
- **Fixture:** a table mapping review attributes to allowed, denied or not allowed (the mock answers per request), `SelfSubjectReview` JSON, an `evaluationError` case, a non-resource item, a denied `escalate` with all rules held.

### k8s.admission (M1 for PSA, engines and SCC; M1-late for webhooks)
- **Measures:** what can reject the product's pods or objects: Pod Security Admission levels on the namespace, policy engines, OpenShift SCCs, and (late) admission webhooks and `ValidatingAdmissionPolicy`.
- **Source, M1 half:** `Namespace` GET labels `pod-security.kubernetes.io/{enforce,audit,warn}` and `-version`; discovery of `security.openshift.io`, `kyverno.io`, `policies.kyverno.io`, `templates.gatekeeper.sh`, `constraints.gatekeeper.sh`. The cluster-wide PSA default lives in the API server config and is not readable; the check says "cluster default not readable". OpenShift syncs PSA labels from SCC annotations and the SCCs are the real gate; RKE2 with the CIS profile and Rancher templates apply cluster defaults the labels do not show. **M1-late half:** `admissionregistration.k8s.io/v1` webhook configurations and `ValidatingAdmissionPolicy` and bindings (GA 1.30). A webhook applies when its `namespaceSelector` matches the namespace labels, its `objectSelector` and `rules` (apiGroups, resources, operations including CREATE) match, with `matchPolicy` considered; non-empty `matchConditions` (GA 1.30) mean "not evaluated, may exempt". For `failurePolicy: Fail` webhooks the backing `Service` and its `discovery.k8s.io/v1` `EndpointSlice` are read (a Service in another namespace needs list rights there, else partial); `endpoints[].conditions.ready` unset means ready; `clientConfig.url` webhooks are "external backend, not verified". Kyverno: `ClusterPolicy` with `validationFailureAction: Enforce` (or per-rule `failureAction`) and the newer `policies.kyverno.io` kinds; Gatekeeper: constraints under `constraints.gatekeeper.sh/v1beta1/<Kind>` with `enforcementAction: deny` (the default) only. Names, kinds and matched namespaces are listed when readable. Optional `dry_run: true` (spec and CLI flag): a server-side dry-run `POST` of the spec's `probe_pod`, with these rules: the manifest is parsed as a typed core `v1` `Pod` and any other kind is rejected; `generateName: rdy-probe-`; an access review for `create pods` first ("dry-run not evaluated: cannot create pods in `{ns}`" if denied); the namespace must exist; a webhook with `sideEffects: Unknown` or `Some` makes the API server refuse dry run, which is reported as `inconclusive: webhook {name} does not support dry-run`, never a block; a pass carries "admitted as `{user}`; workload will run as `{sa}`; SCC and user-based policy exclusions may differ". The dry run is the only way to see the cluster-wide PSA default and real quota and LimitRange effects without creating anything, which is the argument for the flag.
- **Needs:** needs KubeContext, wants cluster-scoped list rights, timeout 30s. Without list rights on webhook configurations: PSA and discovery only, partial.
- **Thresholds:** spec `needs_pod_security: privileged|baseline|restricted` or `uses: [hostPath, hostNetwork, hostPID, privileged, runAsRoot]` (the check derives the minimum level from a three-row table; hostPath, host namespaces and privileged containers need `privileged`; `baseline` forbids all of them), `namespace`, `scc`, `probe_pod`, `dry_run`. PSA `enforce` stricter than needed: block. `warn` or `audit` stricter: warn. `Fail` webhook with no ready endpoint matching the namespace: block. Enforcing policies present: warn with the list and "rerun with the admission dry-run flag to test the product's pod against these". OpenShift detected: warn with the SCC text unless the spec states `scc`.
- **Fix:** "Namespace `{ns}` enforces `{have}`. The product needs `{need}` because it uses `{feature}` (hostPath volumes, host networking and privileged containers all need `privileged`). Either set the level: `kubectl label ns {ns} pod-security.kubernetes.io/enforce={need} --overwrite`, or ask the vendor for chart values that fit `{have}`." OpenShift: "`restricted-v2` requires a UID in the namespace range and drops all capabilities; the usual failure is an image or chart that pins `runAsUser`. First remove `runAsUser` and let the range apply. Only then `oc adm policy add-scc-to-user {scc} -z {sa} -n {ns}`."
- **Fixture:** `Namespace` JSON with label variants and per-distro labels, discovery documents for Kyverno, Gatekeeper and OpenShift, webhook configs with `EndpointSlice` present and empty, `matchConditions`, a `clientConfig.url` webhook, a `ValidatingAdmissionPolicy`, recorded dry-run denial `Status` bodies (`violates PodSecurity "restricted:latest"`), a dry-run refusal for an unsafe webhook, and a guard test that the only non-GET call is the dry-run Pod create.

### k8s.nodes (M1)
- **Measures:** ready nodes, allocatable capacity next to capacity, free capacity on the nodes the product can use, conditions, taints, zones, architecture and OS, kubelet and runtime versions.
- **Source:** `v1` `Node` list: `status.allocatable` and `capacity` (`cpu`, `memory`, `ephemeral-storage`, `pods`, `hugepages-*`; parse quantity forms `7910m`, `Ki` values, plain bytes), `status.conditions`, `spec.taints`, `spec.unschedulable`, labels `topology.kubernetes.io/zone`, `kubernetes.io/arch`, `kubernetes.io/os`, `node.kubernetes.io/instance-type`, `status.nodeInfo`. Counted nodes: `Ready`, not cordoned, `kubernetes.io/os=linux` by default, not Fargate (`eks.amazonaws.com/compute-type: fargate`) or a virtual node, matching `selector`, and either untainted (`NoSchedule` and `NoExecute` only; `PreferNoSchedule` does not exclude) or tolerated by `tolerations`. With no `tolerations` in the spec, tainted GPU pools are excluded. If a node autoscaler is detected (Karpenter via `karpenter.sh` or `karpenter.k8s.aws` discovery, a `cluster-autoscaler` Deployment, EKS Auto Mode or Autopilot labels), a node-count shortfall is a warn "capacity may scale, not verified". Free capacity (the separable half, first to cut) is allocatable minus pod requests: `Pod` list with `fieldSelector=status.phase!=Succeeded,status.phase!=Failed`, effective request per pod (max of init containers and the sum of app containers, plus restartable sidecar init containers and `spec.overhead`); over the 5000 cap, query per matching node with `spec.nodeName`, and that selector carries the same `status.phase` terms, because the read-only guard refuses a Pod list without them. Pod list forbidden or capped: `free` is "not evaluated", never pass.
- **Needs:** needs KubeContext, wants list on nodes and pods, timeout 30s. Node list forbidden (common for namespace-level identities): `partial: needs list nodes`, never a block.
- **Thresholds:** spec values are allocatable, not instance size. The report prints capacity and allocatable side by side: an 8 vCPU, 32 GiB instance shows about 7.9 CPU and 29 GiB allocatable, so write `cpu: 7`, `memory: 28Gi`. `nodes: {min_ready: 3, per_node: {cpu: 7, memory: 28Gi, ephemeral: 100Gi, pods: 30}, free: {cpu: 16, memory: 64Gi, pods: 100}, min_zones, arch: [amd64, arm64] (also accepts x86_64 and aarch64), selector, tolerations}`. Too few ready matching nodes, per-node size too small, or free capacity short: block (warn below 120% of need). The pod-count limit (`allocatable.pods`, for example 17 on a `t3.medium`) is the most common EKS node-level failure and has its own threshold. Pressure conditions on a matching node: warn. `min_zones` has no default; absent zone labels give "not evaluated".
- **Fix:** "Only `{n}` of `{m}` counted nodes have `{mem}` allocatable memory. Add a node group (EKS: `eksctl create nodegroup --cluster {c} --nodes 3 --node-type m6i.2xlarge`) or lower the product's requests."
- **Fixture:** `Node` lists: three healthy, one `NotReady`, one cordoned, a Windows node, a Fargate node, a tainted GPU pool, mixed arm64 and amd64, single zone, an autoscaled single-node cluster; quantity forms; `Pod` lists with requests that use 90% of CPU, with init and sidecar containers, over the cap; a forbidden Pod list and a forbidden Node list (both partial).

### k8s.version (M1)
- **Measures:** server version, distribution, kubelet skew, and whether the API versions the product uses are served.
- **Source:** `GET /version` (`gitVersion` such as `v1.29.4-eks-abc123`; use it, not `major` and `minor`, which carry a `+`). ## 5. Cloud family (`rdy-checks-cloud`, AWS first, M3)

Ids use the provider prefix: `aws.*` now, `gcp.*` and `azure.*` reserved. The crate sits behind a cargo feature `cloud` that is on in release builds, so M1 and M2 builds stay small (the AWS SDK crates are large; the M2 spike measures clean build time, stripped size and peak RAM per target, and decides between the SDK and a thin SigV4 client for the ten EC2 query operations).

**SDK setup.** The SDK is configured, not defaulted: `aws-config` with `default-features = false` and features `rt-tokio`, `sso`, `behavior-version-latest`; every `aws-sdk-*` crate with `default-features = false` and `rt-tokio`; `aws-smithy-http-client` with `rustls-ring` and `default-client`; the client built with `tls_provider(Provider::Rustls(CryptoMode::Ring))` and passed to every client config. The default features pull `aws-lc-sys` (the ADR 0009 ban) and the `credentials-process` feature, which makes `aws-config` run `sh -c <command>` for any profile with `credential_process`; that breaks the no-shell rule (INV-07) and is switched off. A profile with `credential_process` returns `skipped` with "run `aws configure export-credentials --profile {p} --format env` and export the result". CI adds `cargo tree -i aws-lc-sys` (must fail to match).

**Traffic goes through the facade.** One adapter in `rdy-checks-cloud`, `FacadeHttpClient`, implements the SDK `HttpClient` trait and sends each request through the engine's HTTP primitive, which applies the proxy settings and trust store shared with the `net` family (the SDK alone ignores `HTTPS_PROXY`, so `net.egress` would pass while every `aws.*` check timed out), a host allow-list (`*.amazonaws.com` plus the spec `endpoint`), and writes an action-log entry with the AWS request id. SEC-21's link-local refusal exempts the SDK's own credential providers (IMDS, container credentials) by name. If the adapter slips, the minimum is the shared proxy and trust store on the SDK connector plus an SDK interceptor that logs each operation and rejects any operation not on the check's list. Fixtures replay at the facade, so there is one replay point.

**Credentials.** Env, shared profile, SSO cache, container, instance and web identity credentials; process credentials are off. The report names the source that won, inferred from the environment variables and the selected profile (the SDK does not expose it), and warns when both static env keys and `AWS_PROFILE` are set (static keys win). An expired SSO session maps to "SSO session expired, run `aws sso login --profile {p}`", distinct from "no credentials". The whole chain is bounded to 5s with a spec or flag `imds: false`. No region from spec or config: `skipped: no region` with a fix. SDK `tracing` output stays off unless `RUST_LOG` asks (profile names and `sso_start_url` identify the customer). With no credentials every `aws.*` check is `Skipped MissingNeed` (`CloudCredentials(aws)`), which under a block severity is NOT READY by the verdict rule; use `severity: warn` for optional cloud checks. Fix text: "Run `aws sso login --profile {p}` then `export AWS_PROFILE={p}`, or export `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_SESSION_TOKEN`."

**Common spec fields for every `aws.*` check:** `region`, `profile`, `account` (a 12 digit string; `rdy spec lint` rejects a number, because YAML drops a leading zero; a mismatch blocks), `partition` derived from the caller ARN (`aws-cn` and `aws-us-gov` use other ARN prefixes and endpoint suffixes: `skipped: partition not supported yet`), and `trust` and `assume` below.

**Vendor role: inspect first, assume second.** A BYOC role made for a vendor normally trusts the vendor's AWS account with an ExternalId condition, so the customer's operator running `rdy` is not the principal and `sts:AssumeRole` would fail on a correct setup. So the primary path is read-only: `iam:GetRole` on the role to read `AssumeRolePolicyDocument` (the trusted principal account equals the spec's `vendor_account`; an `sts:ExternalId` condition exists, reported as "present", never the value; no `Principal: "*"` without a condition; `MaxSessionDuration` and `PermissionsBoundary` reported), plus `iam:SimulatePrincipalPolicy` with `PolicySourceArn` set to that role (see `aws.iam`). Spec: `trust: {role_arn, vendor_account, external_id_required: true}`. The text never promises that `rdy` proves the vendor's own assume will work. `assume: {role_arn, external_id_env, session_name}` stays for the case where the operator is trusted (an installer role in the customer's own account), with these rules:
1. `external_id_env` must match `^RDY_[A-Z0-9_]{1,60}$` (lint error and runtime refusal otherwise), so a signed spec cannot name `AWS_SECRET_ACCESS_KEY` and have it sent to another account; the value (2 to 1224 characters) is never printed or stored.
2. Consent: without `--allow-assume-role` the check is `skipped: needs --allow-assume-role`. An interactive terminal gets a prompt showing the full role ARN, the target account id, the session name, the variable name (not the value) and "this call is recorded in CloudTrail in account X". A non-interactive run never assumes (the `curl | sh && rdy run --token` flow included). This is `Need::Consent("allow-assume-role")`.
3. The report shows the base and assumed identities side by side (two `GetCallerIdentity` results). Session name is `rdy-<8 hex of the run id>` (characters `[\w+=,.@-]`, max 64) and the report prints the same string. Optionally pass an inline session `Policy` limited to the reader actions; not with `probe: dry_run`.
4. MFA-gated or `SourceIdentity` trust policies are not supported by `assume`; say so in the docs.

**What the audit trail looks like.** Every API call is logged by AWS, including read-only calls: a customer's security team sees tens to hundreds of events from the principal. The text says "makes no change to any resource", not "never writes": `AssumeRole` creates a session, and `SimulatePrincipalPolicy` and DryRun change nothing but are logged. The SDK app name is `rdy/<version>`, so the user agent identifies the tool, and the report prints a filter hint (user agent contains `rdy/` and the run's time range). Each result's evidence lists every call: service, operation, region, selected non-secret parameters (batch size, counts, never `ExternalId` or credentials), HTTP status, error code and the request id (`x-amzn-requestid`). The Source line of each check is its list of allowed operations, and SEC-48 tests against it. Account ids and role ARNs are evidence of class `identifier` (not secret, but they identify the customer); the upload consent text says they are included.

**Reader policy** (published as JSON with a CloudFormation snippet creating a role `rdy-reader` that trusts the operator's own principal; a test compares every operation the checks can call with the policy actions). Every action is read-only: `sts:GetCallerIdentity` (needs no grant), `iam:GetRole`, `iam:SimulatePrincipalPolicy`, `iam:GetContextKeysForPrincipalPolicy` (optional), `iam:ListOpenIDConnectProviders`, `servicequotas:GetServiceQuota`, `servicequotas:GetAWSDefaultServiceQuota`, `servicequotas:ListServiceQuotas`, `servicequotas:ListRequestedServiceQuotaChangeHistoryByQuota`, `cloudwatch:GetMetricData` (no resource-level support, so `Resource` is `*`), `ec2:DescribeRegions`, `ec2:DescribeAvailabilityZones`, `ec2:DescribeInstanceTypes`, `ec2:DescribeInstanceTypeOfferings`, `ec2:DescribeVpcs`, `ec2:DescribeSubnets`, `ec2:DescribeRouteTables`, `ec2:DescribeNatGateways`, `ec2:DescribeInternetGateways`, `ec2:DescribeVpcAttribute`, `ec2:DescribeVpcEndpoints`, `ec2:DescribeSecurityGroups`, `ec2:DescribeAddresses`, `eks:ListClusters`, `eks:DescribeCluster`, `eks:ListAddons`, `eks:DescribeAddon`, `eks:ListNodegroups`, `eks:DescribeNodegroup`, `eks:ListAccessEntries`, `eks:ListAssociatedAccessPolicies`, `ssm:GetParameter` and `ssm:GetParametersByPath` on `arn:aws:ssm:*::parameter/aws/service/global-infrastructure/*` (the partition prefix differs in `aws-cn` and `aws-us-gov`). `sts:AssumeRole` is not in it: it is a grant on the operator, scoped to the role in the spec. Each check's Needs line lists exact action names.

**Fixtures for all of them:** an ordered list of request and response pairs per case, `api/001-iam-GetRole.json` with `{operation, expect_request: {body_subset}, status, headers_subset, body}`, replayed at the facade. Cases every check shares: `AccessDenied` on each call (partial with the action named), throttling with a retry that succeeds and one that exhausts the budget, pagination (`IsTruncated` and `Marker`, `NextToken`), an expired SSO token, an IMDS timeout, static env keys overriding a profile, a profile with `credential_process` (expect `skipped`), an `aws-cn` ARN (expect `skipped`). Tests use a controlled clock (SDK `TimeSource`) and a fake sleep. The recorder drops `Authorization` and `X-Amz-Security-Token`, and a golden test scans all `api/` files for `AKIA` and `ASIA` patterns that are not the `EXAMPLE` values. Account `111122223333`, keys `AKIAIOSFODNN7EXAMPLE`.

Checks share one lazily built `AwsSession` per run (credentials, region, partition, caller identity) held in the cloud family, so there is no "identity runs first" ordering dependency; each check also writes the caller identity it used into its own evidence.

### aws.iam (M3; cloud-iam-expert reviews)
- **Measures:** whether the principal the installer will use is allowed each listed action, on the listed resources, with the listed context. Results are labelled "simulated".
- **Source:** `iam:SimulatePrincipalPolicy` with `PolicySourceArn` set to the user or role ARN, `ActionNames` in batches of 50 (a house choice, not an AWS limit; each name is 3 to 128 characters), `ResourceArns` per action from the spec (default `*`; `ec2:RunInstances` and similar set `ResourceHandlingOption`, for example `EC2-VPC-EBS-Subnet`, which needs instance, image, security group, network interface, subnet and volume ARNs), `ContextEntries` from the spec, `MaxItems` 1000, paged. Details that matter: (1) the API takes a user, group or role ARN, not an assumed-role session ARN, so for `arn:aws:sts::111122223333:assumed-role/NAME/session` the check calls `iam:GetRole` for `NAME` and uses the returned `Role.Arn`, never a hand-built path (IAM Identity Center roles live under `/aws-reserved/sso.amazonaws.com/` and, outside us-east-1, `/aws-reserved/sso.amazonaws.com/eu-west-1/`); if `GetRole` is denied, try `arn:aws:iam::{acct}:role/{NAME}` once, else use the dry-run path or return `unknown`; federated-user and root cannot be simulated and return `unknown` with a reason; instance-profile and IRSA sessions resolve as `assumed-role` and work the same. (2) The caller needs `iam:SimulatePrincipalPolicy` on that principal, which install roles often lack. (3) Per the API reference the simulator evaluates identity policies, permissions boundaries and service control policies including their condition keys and resource scoping, and takes only the context the call supplies; it does not evaluate session policies, resource policies for roles, RCPs or VPC endpoint policies, and its results "can differ from your live environment"; the evidence lists what was and was not evaluated. A result with `MissingContextValues` optionally calls `iam:GetContextKeysForPrincipalPolicy` so the warn text lists the keys the policy really uses. Fallback (opt-in, `probe: dry_run`): the EC2 API with `DryRun=true` (`DryRunOperation`, HTTP 412, means allowed; `UnauthorizedOperation`, 403, means denied). A dry run goes through real authorization including SCPs and conditions and creates nothing, but it tests only the calling principal (`principal:` with `probe: dry_run` is a lint error), placeholder parameters can produce validation errors (`InvalidAMIID.NotFound`) instead of an authorization answer (any error other than the two codes is `unknown`, never pass), some EC2 actions have no `DryRun` parameter (an explicit table `ec2_dryrun.toml` maps action to operation and minimal parameters), and `UnauthorizedOperation` calls are the classic alarm in CIS-style alerting on unauthorized API calls, so the report says "this run made N DryRun calls; AWS logs them as errors in CloudTrail". Non-EC2 actions with no simulate permission are `unknown`, or `probe: call` makes a real read call for `Describe*` and `List*` actions.
- **Needs:** needs CloudCredentials(aws), wants `iam:GetRole` and `iam:SimulatePrincipalPolicy`; explicit per-call timeout with `RetryConfig::standard()` (3 attempts); 20 calls and 45s budget; the report says which batches finished.
- **Thresholds:** spec `simulate: [actions]` (plan example), `resources: {action: [arns]}`, `context: {key: value}`, `probe: simulate|dry_run|call` (default `simulate`), `principal: <arn>`, `trust` (above). Decision `implicitDeny` or `explicitDeny`: block. `OrganizationsDecisionDetail.AllowedByOrganizations = false` is an SCP block even when `EvalDecision` is `implicitDeny`. `allowed`: pass. Denied with `MissingContextValues`: warn "depends on `{keys}`, supply them in `context`". Cannot probe at all: warn, never block.
- **Fix:** "`{principal}` is not allowed `ec2:CreateSecurityGroup` (implicit deny, simulated). Add it to the role's policy: `{\"Effect\":\"Allow\",\"Action\":\"ec2:CreateSecurityGroup\",\"Resource\":\"{resource}\"}`" (a resource-scoped example when the spec gave `resources`, `*` otherwise). SCP: "A service control policy blocks this. Members cannot read SCPs: ask the AWS Organizations admin to allow `{action}` for account `{a}` in the SCPs that apply." Permissions boundary: "The role's permissions boundary does not allow it."
- **Fixture:** `SimulatePrincipalPolicy` responses: all allowed, `implicitDeny`, `explicitDeny` with the org detail false, `implicitDeny` with org detail false, `MissingContextValues`, a paged result, `AccessDenied` on the simulate call; `GetRole` for a plain role, an SSO path and a regional SSO path, and denied; federated-user and root ARNs; EC2 `DryRunOperation` (412), `UnauthorizedOperation` (403) and a validation error; trust-policy cases (correct vendor policy, missing ExternalId condition, wildcard principal).

### aws.quota (M3)

### aws.vpc (M3)
- **Measures:** subnet capacity and layout, routes, NAT, VPC DNS attributes, private endpoints.
- **Source:** `ec2:DescribeVpcs`, `DescribeSubnets` (`AvailableIpAddressCount`, which already excludes the 5 reserved addresses; AZ; tags `kubernetes.io/role/elb`, `kubernetes.io/role/internal-elb`, `kubernetes.io/cluster/<name>`), `DescribeRouteTables` (a subnet with no explicit association uses the main table, `Associations[].Main = true`; `State = blackhole` is broken; `::/0` and egress-only gateways `eigw-` count for IPv6; routes to `tgw-`, `vgw-`, `pcx-` or a firewall endpoint are "other path, cannot verify" and warn, not block, when the spec says `internet: nat`), `DescribeNatGateways` (state `available`, sits in a subnet whose table has an `igw-` default route), `DescribeInternetGateways`, `DescribeVpcAttribute` (one attribute per call: `enableDnsSupport` and `enableDnsHostnames`, two calls per VPC in the budget), `DescribeVpcEndpoints` and `DescribeSecurityGroups`. Endpoint reachability, not only existence: interface endpoint subnets cover the workload AZs; the endpoint security group allows 443 from the node CIDR; gateway endpoints (S3) are associated with the subnets' route tables (`PrivateDnsEnabled` does not apply to them); private DNS needs both DNS attributes; a custom endpoint policy is "present, not evaluated". When `rdy` runs inside the VPC an optional probe resolves the endpoint host through `net` code and expects a private address inside the VPC CIDR, then connects to 443. IPv6-only and dual-stack clusters are not covered; the text says so.
- **Needs:** needs CloudCredentials(aws), the `ec2:Describe*` actions named above, timeout 20s.
- **Thresholds:** spec `vpc_id` or `subnet_ids`, `min_azs`, `nodes` (per AZ or total), `pods_per_node`, `cni_mode: secondary_ip|prefix`, `internet: nat|igw|none`, `endpoints: [com.amazonaws.<region>.ecr.api, ...ecr.dkr, ...s3, ...sts, ...ec2]`, `dns_hostnames: true`. Too few AZs or free IPs, missing route, DNS attribute off, endpoint missing or not `available`: block. - **Fix:** "Subnet `{id}` in `{az}` has `{n}` free IPs, `{need}` needed. Add a secondary CIDR (`aws ec2 associate-vpc-cidr-block --vpc-id {v} --cidr-block 100.64.0.0/16`), new subnets, and VPC CNI custom networking (an `ENIConfig` per AZ) before pods use them. Prefix delegation helps only with free contiguous /28 blocks."
- **Fixture:** EC2 XML responses: roomy subnets, two subnets in one AZ, 9 free IPs, no explicit association (main table), blackhole route, NAT `pending`, DNS hostnames off, endpoint pending, endpoint security group closed, paged subnets.

### aws.region (M3)
- **Measures:** region is enabled for the account, enough AZs, instance types offered in enough AZs, services available in the region. "Offered" is not "capacity available": `InsufficientInstanceCapacity` can still happen, especially for GPU types.
- **Source:** `ec2:DescribeRegions` with `AllRegions=true` (`OptInStatus`), called from a region that is already enabled (the spec region if enabled, else the profile default; a not-enabled region's EC2 endpoint is unusable). `DescribeAvailabilityZones` filtered to `zone-type = availability-zone` and `state = available` (Local and Wavelength Zones appear only with `AllAvailabilityZones`). Zones are reported by `ZoneId` (`use1-az1`), because names map to different physical zones per account. `DescribeInstanceTypeOfferings` with `LocationType=availability-zone` and filter `instance-type` (paged with `NextToken`), `DescribeInstanceTypes`. Service availability from the documented Systems Manager public parameters: `GetParametersByPath` on `/aws/service/global-infrastructure/services/<svc>/regions` (each value is a region name) or `GetParameter` on `/aws/service/global-infrastructure/regions/<region>/services/<svc>/endpoint`. These queries are supported only in 17 regions (us-east-1, us-east-2, us-west-1, us-west-2, ap-east-1, ap-south-1, ap-northeast-1, ap-northeast-2, ap-southeast-1, ap-southeast-2, ca-central-1, eu-central-1, eu-west-1, eu-west-2, eu-west-3, eu-north-1, sa-east-1), so the check calls the spec region if listed, else the nearest listed one (`ssm_region` overrides). SSM service codes (`eks`, `bedrock`) are short names that spec authors may not guess; the docs list them. In `aws-cn` and `aws-us-gov` the check is `skipped`.
- **Needs:** needs CloudCredentials(aws), the `ec2:Describe*` actions and optionally `ssm:GetParameter*`, timeout 20s.
- **Thresholds:** spec `region`, `ssm_region`, `min_azs`, `instance_types: [g5.xlarge, m6i.2xlarge]`, `services: [eks, bedrock]`. Region `not-opted-in`: block. Instance type offered in fewer than `min_azs` AZs: block (GPU types are often offered in only some). From SSM: `ParameterNotFound` in a supported region is warn "AWS public data lists no `{svc}` in `{r}`; confirm in the console", and `AccessDenied`, throttling or an unsupported-region answer is `unknown`, never block (an SCP that denies `aws:RequestedRegion` outside the customer's regions would otherwise read as "service missing"). - **Fix:** "Region `{r}` is not enabled for this account. Enable it (Account settings, AWS Regions; check the console wording when the docs are written) or `aws account enable-region --region-name {r}`, which needs `account:EnableRegion`; it takes minutes to hours." Capacity: "Offered is not guaranteed: for GPU types ask for an On-Demand Capacity Reservation." SSM: "This is AWS's published list and may lag a new service or region." - **Fixture:** `DescribeRegions` with an opt-in region, offerings for `g5.xlarge` in two of three AZs (paged), a missing SSM parameter in a supported region, an unsupported region, an SCP region deny, an `aws-cn` ARN.

## 6. GPU family (`rdy-checks-gpu`, M4)

GPU checks are Linux and Windows. macOS: not applicable (no CUDA). The host `gpu.*` checks examine the machine running `rdy`. On Kubernetes, where `rdy` usually runs on a laptop, `k8s.device_plugins` is the check that ranks first and covers the cluster. A required GPU that was not examined must not read as green: on a machine with no NVIDIA GPU, or with no usable tooling, a `gpu.*` check returns a Block "GPU hardware was not examined on this machine ({reason}); run `rdy` on the GPU node or use `k8s.device_plugins` for clusters" under the spec severity, never `NotApplicable`. The PCI scan reads `class` as well as `vendor`: only display and 3D controller classes (`0x03xxxx`) with vendor `0x10de` count, because the vendor id alone also matches a GPU's HDMI audio function and NVSwitch bridges. Three results stay distinct: `NVIDIA GPU present, no driver`, `no NVIDIA GPU`, and `GPU bound to vfio-pci` (a hypervisor host, valid).

**Data source (ADR 0006 item 6).** One call, `nvidia-smi -q -x` (XML), plus `/proc` and `/sys` reads. A static musl binary cannot `dlopen` the glibc-only `libnvidia-ml.so.1`; `nvidia-smi` is an ordinary glibc binary and works as a child process. Revisit triggers, not work: an optional glibc build or a tiny NVML helper binary, only if a design partner needs something `nvidia-smi` cannot print, or probe time under one second becomes a hard need. Every Source line names the NVML call that returns the same value. Rules:
- **Gate on the kernel side.** `nvidia-smi` invokes `nvidia-modprobe` (setuid root), which can load the kernel module and create `/dev/nvidia*`, changing the machine and masking the very failure `rdy` exists to report. Every `nvidia-smi` call runs only after `/proc/driver/nvidia/version` is readable or `/sys/module/nvidia` exists. If not, "driver not loaded" is classified from files alone and the tool is not run. A fixture asserts it was never called. Command policy: "GPU tools only run after the kernel side is seen". `rdy` never calls `--gpu-reset`, `-mig`, `-pm`, `-c` or `dcgmi diag`.
- **Tool search list** (ordered; the one used is recorded): `/usr/bin`, `/usr/local/nvidia/bin`, `/usr/local/nvidia/toolkit`, `/run/nvidia/driver/usr/bin` (GPU Operator driver container), `/home/kubernetes/bin/nvidia` (GKE), `/usr/lib/wsl/lib`, then Windows paths (`nvidia-smi.exe` in `System32`, or the NVSMI directory). If `/proc/driver/nvidia` exists but no tool is found: "driver loaded, tool not found", not "no tooling". `nvcc` is found by absolute path `/usr/local/cuda/bin/nvcc` as a fallback after `version.json`.
- **Failure classification:** by exit code first (9 driver not loaded, 12 NVML library not found, which inside a container usually means `NVIDIA_DRIVER_CAPABILITIES` lacks `utility`, 14 infoROM corrupted, 15 GPU fell off the bus, 4 no permission, 255 other), then by string (`couldn't communicate with the NVIDIA driver`, `Driver/library version mismatch`, `No devices were found`, `Unknown Error`, `GPU is lost`), then require that stdout starts with `<?xml`. `-x` prints text, not XML, on error. A timeout is `warn: indeterminate` unless a second attempt also hangs or `/proc/driver/nvidia/gpus/*/information` is unreadable, then block "GPU or driver is wedged, check dmesg for Xid"; the abandoned PID goes into evidence. After the first hang a circuit breaker in the GPU layer stops `nvlink -s`, `topo -m` and the `compute_cap` query, each of which would leak another stuck process.
- **Timeouts:** 30s for the shared XML call (the first `nvidia-smi -q` on an 8 GPU HGX with persistence mode off can exceed 10s), 15s for the others, and a progress line after 5s ("nvidia-smi is slow; persistence mode off?"). Output cap 2 MiB; a larger output is `truncated`, the result `partial`, and cut XML is never parsed.
- **Parser:** by tag name, never position; XML parser that fetches no external DTD and expands no entities (`quick-xml` or `roxmltree`); units parsed (`81559 MiB`, `34 C`, `16x`, `[N/A]`, `Not Supported`); three states per value (present, `N/A` or `Not Supported`, tag absent). A required tag absent makes the result `partial` ("this driver does not report X"), never pass. NVIDIA publishes no tag list, only the DTD from `nvidia-smi -q -x --dtd`; every fixture is recorded with its DTD, the DTD is committed next to the XML, and a test asserts that every tag path the code reads exists in each fixture generation's DTD. Tag names below are from recollection and must be checked against a recorded DTD before coding.
- **Special hosts:** WSL2 (`/proc/sys/kernel/osrelease` contains `microsoft`, `/dev/dxg` exists): only the XML path runs; kernel module, nouveau, Secure Boot and persistence are `NotApplicable`. vGPU guests: ECC and fabric health `NotApplicable`, VRAM evaluated against the profile size, licence status shown as evidence with a warn if unlicensed. Unified-memory systems (Jetson, DGX Spark class): VRAM `N/A` gives `partial`, not a block.
- **Privacy:** serial number, board id and part number are never recorded; UUIDs are hashed; process lists are reduced to a count and total memory in JSON (names only in local HTML if the user asks). The scrub tool and the redaction golden tests cover this.
- **Shared layer:** one memoised collector, owned by a detached task, so a per-check timeout drops only that check's wait. If `gpu.driver` fails, the other checks return a skipped-with-cause `caused_by: gpu.driver`, rendered as one block and "depends on gpu.driver" lines.
- **Fixture capture:** the founder has no GPUs and fixtures are synthetic. Capture on rented machines (a T4, A10G or L4 instance; one A100 on a cloud that allows MIG; an HGX capture from a design partner through the scrub script), always with `-q -x --dtd`. `tools/scrub-nvidia-xml` replaces UUID, serial, board id, part number, bus id and process names with fixed fake values, and a test fails if a committed fixture contains a real-shaped UUID. Failure cases (row remap failure, lost GPU) are hand-edited from a clean capture. A review ticket for tag names and the DTD comes before the shared layer ticket.

### gpu.driver (M4)
- **Measures:** driver loaded and working, version, open or proprietary kernel module, `nouveau` conflict, DKMS state, Secure Boot state, persistence daemon.
- **Source:** L: `/proc/driver/nvidia/version` (line `NVRM version: NVIDIA UNIX Open Kernel Module ...` or `NVIDIA UNIX Kernel Module ...`; the architecture word varies, for example `aarch64` on Grace, so the pattern does not name x86_64), `/sys/module/nvidia/version`, `/proc/modules` (`nvidia`, `nvidia_uvm`, `nvidia_modeset`, `nouveau`), device nodes `/dev/nvidiactl`, `/dev/nvidia0`, `/dev/nvidia-uvm`. The most frequent "driver installed, not working" cause is a kernel update where DKMS did not rebuild the module: look in `/lib/modules/$(uname -r)/` (under `updates/dkms` and `kernel/drivers/video`) for `nvidia.ko*`, and report "module built for another kernel". The user-space version comes from the file name `libnvidia-ml.so.<ver>` by directory listing (no loading, and no `modinfo`). Secure Boot from `/sys/firmware/efi/efivars/SecureBoot-8be4df61-93ca-11d2-aa0d-00e098032b8c` (fifth byte `1`) and `/sys/kernel/security/lockdown`; the diagnosis "unsigned module" needs Secure Boot on, the module file present and not loaded. `nvidia-persistenced` by first token of `/proc/*/cmdline`. XML `driver_version` and `attached_gpus`; mismatch is `/sys/module/nvidia/version` against the user-space version. NVML: `nvmlSystemGetDriverVersion`, `nvmlSystemGetNVMLVersion`, `nvmlDeviceGetCount_v2`. W: `nvidia-smi.exe`, same XML; the driver version has two parts (`551.61`). WSL2 and M: see the shared rules.
- **Needs:** none, timeout 30s (shared call).
- **Thresholds:** spec `min: "535.104"`, `kernel_module: open|proprietary|any`, `persistence: required|any`. Versions compare numerically per component (`535.54.03` is below `535.104.05`). Driver not loaded, below `min`, or mismatched: block. `nouveau` loaded: block. Module built for another kernel: block. Wrong flavour: block; the text says that open modules support Turing and newer only, the newest generation supports only the open module, and Pascal and Volta need the proprietary one, so `kernel_module: open` on a V100 can never pass (`gpu_arch.toml`: `open_module_ok`, `min_driver`). Persistence: warn only when `required`, or when the first call took over 5s (where it explains the slow call).
- **Fix:** "Driver/library version mismatch: the kernel module is `{k}` and the libraries are `{u}`. Reboot (first choice). Unloading the modules (`rmmod nvidia_uvm nvidia_drm nvidia_modeset nvidia`) fails or hangs while persistenced, DCGM, the fabric manager or containers hold them: stop services that use the GPU first." DKMS: "Run `dkms status` and `dkms autoinstall`; install kernel headers if missing." Nouveau: "Create `/etc/modprobe.d/blacklist-nouveau.conf` with `blacklist nouveau` and `options nouveau modeset=0`, run `dracut --force` (RHEL) or `update-initramfs -u` (Debian), reboot."
- **Fixture:** recorded `nvidia-smi -q -x` and its DTD for a healthy node (open module, 550.x) and 535, 525 generations; every failure exit code and string; `/proc/driver/nvidia/version` for both flavours and `aarch64`; a module-absent case where the runner asserts `nvidia-smi` was never called; a fake `efivars` file; a DKMS-stale tree; operator layout with the tool under `/run/nvidia/driver/usr/bin`; a runner that sleeps forever (timeout case); WSL2 case.

### gpu.runtime (M4)
- **Measures:** NVIDIA Container Toolkit installed and registered with the runtime the product uses.
- **Source:** L: `nvidia-ctk` and `nvidia-container-runtime` found on the same ordered search list (the GPU Operator installs the toolkit under `/usr/local/nvidia/toolkit/`), `nvidia-ctk --version`; `/etc/nvidia-container-runtime/config.toml`; Docker `/etc/docker/daemon.json` (`runtimes.nvidia`, `default-runtime`, `features.cdi`); containerd `config.toml` parsed as TOML (not grep), following `imports`, in both schema versions, plus drop-ins under `/etc/containerd/conf.d/` (later `nvidia-ctk` releases write one; unconfirmed until a fixture shows it) and the Rancher paths (k3s `/var/lib/rancher/k3s/agent/etc/containerd/config.toml`, RKE2 `config.toml.tmpl`); `enable_cdi`; CDI specs `/etc/cdi/nvidia.yaml` and `/var/run/cdi/nvidia.yaml`, comparing the driver version inside the spec file to the loaded driver (a stale spec after a driver upgrade is a frequent failure); CRI-O `/etc/crio/crio.conf.d/*`. Unreadable config: `partial` "run as root to read X", never block. W: `NotApplicable` (Windows containers do not use `nvidia-ctk`). M: not applicable.
- **Needs:** wants Root, timeout 5s.
- **Thresholds:** spec `container_runtime: docker|containerd|crio`, `min_toolkit: "1.14"`, `cdi: required|any`. Toolkit missing while containers are in scope: block. Installed but not registered with the active runtime: block. Stale CDI spec: block. Version below `min_toolkit`: warn.
- **Fix:** "Register the runtime: `nvidia-ctk runtime configure --runtime=containerd --set-as-default && systemctl restart containerd` (use `--runtime=docker` for Docker). For CDI: `nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml`, and again after any driver change."
- **Fixture:** daemon and containerd config variants (v2, v3, drop-in, Rancher), operator-layout toolkit files, CDI YAML with matching and stale versions, a root-less run.

### gpu.cuda (M4)
- **Measures:** the CUDA version the installed driver supports, against what the product was built with, and the toolkit on the host if the spec asks.
- **Source:** XML `cuda_version` (NVML: `nvmlSystemGetCudaDriverVersion_v2`, integer `12040` means 12.4). The plain `nvidia-smi` header line is not parsed. Toolkit (`source: toolkit`): `/usr/local/cuda/version.json` (`cuda.version`), older `version.txt`, then `nvcc --version` ("release 12.4") by absolute path; `libcudart.so.*` in `/usr/local/cuda*/lib64` and the distro library directory. W: same through `nvidia-smi.exe` and `%CUDA_PATH%\version.json`.
- **Needs:** none, timeout 30s (shared call).
- **Thresholds:** spec `built_with: "12.4"` (replaces the ambiguous `min` of the plan example), `source: driver|toolkit` (default `driver`), `compat: minor|strict|forward` (default `minor`), `max`. CUDA minor version compatibility lets an application built with any 12.x toolkit run on a driver at or above the major floor, with limits (no PTX JIT of newer code, some newer features unavailable). `minor`: pass if the driver is at or above the major-version floor (11.x: 450, 12.x: 525.60.13, 13.x: 580), with a note that PTX JIT and newer features are not covered. `strict`: the GA row of `cuda_driver_min.toml` for `built_with`. `forward`: pass if the GPU is data centre class (`datacenter: true` in `gpu_arch.toml`, never inferred from `product_brand`, which reads only "NVIDIA" on current cards) and the product declares it ships `cuda-compat`; `rdy` cannot see inside the container, so the text says "plausible", not "verified". Below the applicable rule: block. Above `max`: warn. Card below compute capability 7.5 with `built_with` 13.x: warn (CUDA 13 dropped Maxwell, Pascal and Volta; R580 is the last driver branch for them).
- **Fix:** "The driver supports CUDA `{have}`; the product was built with `{built_with}`. With `compat: strict` upgrade the driver: CUDA 12.2 needs 535.54.03 or newer, CUDA 12.4 needs 550.54.14 or newer (Linux; table in Appendix B)."
- **Fixture:** XML for drivers 525, 535, 550 with DTDs; `version.json`; `nvcc --version` output; a compat directory; Windows two-part versions.

### gpu.model_egress (M4)
- **Measures:** model hubs and registries are reachable from here, which hosts they redirect to, ranged download works, and the model cache path has room. Air-gapped mode checks the local copy instead.
- **Source:** shared helper functions that `rdy-checks-gpu` takes from the shared module (HTTP stage code, redirect recorder, `statvfs`), not through the other check crates. For each spec source URL: unauthenticated `GET` with `Range: bytes=0-{range_bytes}` (default 8 MiB), redirects not followed: the `Location` host is recorded and the text says "redirects to `{host}`; add it to `sources` to test it". Hosts and never paths or queries go into evidence (redirect URLs carry signed query strings). OCI registry sources (container images, NGC) are delegated to `net.registry`. Offline mode: if `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1` or `HF_ENDPOINT` points at a mirror, the check probes the mirror, not the public hub, or checks `offline_paths: [{path, files, min_size}]` with file sizes and `statvfs` only, and says which mode ran. Reads those variables by name, and `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE` by name. Never reads or sends a token; a gated model answering 401 or 403 is `warn: needs a token, cannot verify`. Speed: a sample of at least 32 MiB or 10s (8 MiB measures TCP slow start).
- **Needs:** needs Network, 30s per source.
- **Thresholds:** spec `sources: [url]`, `offline_paths`, `cache_path` and `cache_need`, `range_bytes`, `min_mbps`. Source unreachable or a listed host blocked: block, naming the host. An unlisted redirect host: warn "not tested". No range support: warn (resumable downloads fail). Under `min_mbps`: warn. Cache disk short: block. Local model missing or short in offline mode: block.
- **Fix:** "`{hub}` is reachable but the file is served from `{cdn}`. Add it to `sources` and allow `{cdn}:443`. The Python client may use different hosts (the Xet download path) and a different trust store: behind TLS interception set `SSL_CERT_FILE` or `REQUESTS_CA_BUNDLE` in the container. `HF_HUB_DISABLE_XET=1` is a documented workaround, not a recommendation."
- **Fixture:** loopback server with `302` to a second loopback host, `206` and `200` modes, a `401` gated file, a slow-start throttled body; a fake cache directory and offline model tree; the three CA variables set and unset.

### gpu.devices (M4; one ticket with `gpu.vram`)
- **Measures:** GPU count, models, architecture, compute capability, MIG state, compute mode, persistence, virtualization mode, PCIe link width.
- **Source:** XML per GPU: `product_name`, `product_architecture`, `uuid`, `pci/pci_bus_id`, `compute_mode`, `persistence_mode`, `mig_mode` (`current_mig`, `pending_mig`), `gpu_virtualization_mode/virtualization_mode` (values `None`, `Pass-Through`, `VGPU`, `Host VGPU`), `pci/pci_gpu_link_info/pcie_gen` and `link_widths` (`max_link_width`, `current_link_width`, values like `16x`). Link generation is not compared because it drops at idle. Compute capability: `nvidia-smi --query-gpu=index,compute_cap --format=csv,noheader` where the driver supports `compute_cap`, else the architecture table (a range, not a number, for families). The variables `CUDA_VISIBLE_DEVICES` and `NVIDIA_VISIBLE_DEVICES` are recorded by name and value class (empty, `all`, a list). NVML: `nvmlDeviceGetName`, `nvmlDeviceGetArchitecture`, `nvmlDeviceGetCudaComputeCapability`, `nvmlDeviceGetMigMode`, `nvmlDeviceGetComputeMode`, `nvmlDeviceGetPersistenceMode`, `nvmlDeviceGetVirtualizationMode`, `nvmlDeviceGetCurrPcieLinkWidth`. MIG: when `Enabled`, `min_per_gpu` and `count` are evaluated against instances (a `1g.10gb` slice is about 9.75 GiB), MIG on with zero GPU instances is a block when the product needs GPUs, and `pending_mig` different from `current_mig` is a warn (needs a reset).
- **Needs:** none, timeout 30s (shared call).
- **Thresholds:** spec `count` (GPUs matching `models`), `models: [regex]`, `compute_capability: "8.0"`, `mig: forbid|require|any`, `compute_mode: default`, `virtualization: passthrough|vgpu|any`. Count short, model not allowed, capability below minimum, MIG state wrong: block. Mixed models when `count > 1`: warn. Compute mode `Exclusive_Process` or `Prohibited` when `default` wanted: warn. PCIe width below max: warn, skipped when virtualization is not `None`.
- **Fix:** "MIG is enabled on GPU 0 but the product needs whole GPUs. Drain the workloads, then disable it with `nvidia-smi -i 0 -mig 0` and reset the GPU or reboot. `rdy` never runs this itself." Compute mode: "`nvidia-smi -i 0 -c DEFAULT` after stopping GPU workloads."
- **Fixture:** XML for 8x H100 SXM, 4x L4, T4 (capability 7.5), A100 with MIG on and with `pending_mig`, MIG on with no instances, a vGPU guest, a GPU at PCIe x8, mixed models, with DTDs.

### gpu.vram (M4)
- **Measures:** VRAM per GPU, how many GPUs meet the need, free VRAM now, MIG instance sizes.
- **Source:** XML `fb_memory_usage` (`total`, `reserved`, `used`, `free`, MiB; `reserved` is missing on older drivers) per GPU; for MIG the per-instance memory in the `mig_devices` section. NVML: `nvmlDeviceGetMemoryInfo_v2`. Reported values explain the nominal band: A100 80GB 81920 MiB, H100 80GB about 81559 MiB, H200 about 143771 MiB, L4 about 23034 MiB and A10G about 22731 MiB for "24 GB" (the last two from memory, confirm on capture).
- **Needs:** none, timeout 30s (shared call).
- **Thresholds:** spec `min_per_gpu: 24Gi` (the real need, not the marketing size), `count: 4` (GPUs meeting it), `min_total`, `min_free`, `band` (default 8%), `band_result: pass|warn` (default `pass`). Inside the band: pass with a note, so an H100 and an A100 give the same result for `80Gi`. Fewer than `count` GPUs meeting `min_per_gpu`: block. Free below `min_free`, or more than 10% used by other processes: warn "GPU is busy" (process count and total memory only).
- **Fix:** "GPU 0 (`{name}`) has `{have}`, the product needs `{min}`. Use a larger GPU class (48 GB or 80 GB) or reduce per-GPU model size with tensor parallelism." Busy: "`nvidia-smi` shows `{n}` processes holding `{mem}`."
- **Fixture:** XML for H100 (81559 MiB), A100 (81920), L4 (23034), a MIG-enabled A100 with 1g.10gb instances, a GPU with 40% used, a unified-memory `N/A`.

### gpu.fabric (M4)
- **Measures:** GPU interconnect and cluster-fabric prerequisites: NVLink links, NVSwitch fabric manager, InfiniBand or RoCE ports, GPUDirect RDMA, NCCL prerequisites.
- **Source:** L: `nvidia-smi nvlink -s` (link up and speed) and `nvidia-smi topo -m` (matrix of `NV#`, `PIX`, `PXB`, `PHB`, `NODE`, `SYS`; no root needed); NVSwitch presence `/proc/driver/nvidia-nvswitch/` and `/dev/nvidia-nvswitch*`; the fabric manager by first token of `/proc/*/cmdline` or the systemd unit state (`comm` is cut to 15 characters, so `nv-fabricmanager` reads `nv-fabricmanage` and `nvidia-persistenced` reads `nvidia-persiste`; matching `comm` exactly would block every healthy HGX), with the XML `fabric` state and status (`Completed`, `Success`; layout to confirm against the DTD) as primary evidence and the process as secondary; its version from `nv-fabricmanager -v`, which must equal the driver version. InfiniBand `/sys/class/infiniband/*/ports/*/{state,rate,link_layer}` (`4: ACTIVE`, `400 Gb/sec (4X NDR)`); `INIT` means no subnet manager only on InfiniBand, and on RoCE (`link_layer` Ethernet) the check wants `ACTIVE` and notes that PFC and ECN cannot be seen from the host; IB checks run only when the spec asks. GPUDirect RDMA from `/proc/modules` (`nvidia_peermem`, legacy `nv_peer_mem`). `libnccl.so.2` is reported, never failed on (PyTorch wheels bundle NCCL); environment variables `NCCL_SOCKET_IFNAME` and `NCCL_IB_DISABLE` by name. The host `/dev/shm` says nothing about the 64 MiB container default that breaks NCCL in pods, so that is in the fix text, not a host threshold. PCIe ACS detail via `lspci -vv` is dropped from M4 (not in Appendix A). NVML: `nvmlDeviceGetNvLinkState`, `nvmlDeviceGetGpuFabricInfo`. W, M: not applicable. A real all-reduce test is not a built-in check; it is a `custom.exec` recipe in `examples/specs/` (`all_reduce_perf -b 8 -e 128M -f 2 -g {n}`, with a `busbw` threshold).
- **Needs:** wants Root, timeout 15s.
- **Thresholds:** spec `nvlink: required|any|none`, `fabric_manager: required`, `ib: {ports: 4, min_gbps: 200}`, `peermem: required`. NVSwitch present but fabric manager down or version-mismatched: block (symptom: CUDA error 802, system not ready). NVLink down where required: block. IB port not `ACTIVE`: block. `nvidia_peermem` missing when required: block.
- **Fix:** "NVSwitch system, `nvidia-fabricmanager` is not running. Install the package that matches driver `{v}` and start it: `systemctl enable --now nvidia-fabricmanager`. Its version must equal the driver version. In pods, give NCCL shared memory with an `emptyDir` with `medium: Memory` or `--shm-size`."
- **Fixture:** fake `sys/class/infiniband` trees (active, init, down, RoCE), recorded `nvlink -s` and `topo -m` output, fabric manager version strings, a `comm`-truncation process tree, `proc/modules` with and without `nvidia_peermem`.

### gpu.health (M4)
- **Measures:** signs a GPU or its memory is failing, and recent kernel Xid errors.
- **Source:** XML: `ecc_mode`, `ecc_errors` (two layouts across drivers: `volatile` and `aggregate` with `sram_*` and `dram_*`, or older `single_bit` and `double_bit`), `retired_pages` (older drivers: `pending_blacklist`), `remapped_rows` (`remapped_row_failure`, `remapped_row_pending`, `remapped_row_corr`, `remapped_row_unc`), `clocks_event_reasons` (`clocks_event_reason_*`, values `Active` and `Not Active`; older `clocks_throttle_reasons`), temperature and power. NVML: `nvmlDeviceGetTotalEccErrors`, `nvmlDeviceGetRetiredPages`, `nvmlDeviceGetRemappedRows`, `nvmlDeviceGetCurrentClocksEventReasons`, `nvmlDeviceGetTemperature`. Xid: `/dev/kmsg` opened with `O_NONBLOCK` and read record by record until `EAGAIN` (an unbounded read blocks forever and a blocked `spawn_blocking` task cannot be cancelled), capped at 1 MiB total; records start `priority,seq,timestamp_us,flags;`, timestamps are microseconds since boot, so a window needs `/proc/uptime`; fallback `/var/log/kern.log` and `/var/log/messages` when `dmesg_restrict` blocks; in containers "kernel log not visible". Parse `Xid \(PCI:([0-9a-f:.]+)\): (\d+)`, not the whole line. A GPU reset or driver reload does not clear the ring, so if `nvidia-smi` is healthy after the Xid the result is a warn "seen at T, GPU responds now", not a block.
- **Needs:** wants Root (Xid), timeout 15s. Without root: hardware counters only, "kernel log not visible" (partial).
- **Thresholds:** `xid.toml` (Appendix B) sets the default classes: block for 48, 64, 79, 95, 119, 120, 140; warn for 74 (serious on NVSwitch systems) and 92; info for 13, 31, 43, 45, 63, 94 (13 and 31 are almost always application faults; 63 is informational). Spec `xid_window: 24h`, `block_xids` overrides. ECC: warn on volatile uncorrectable counters (since last reset); aggregate counters are info (a page retired years ago is fine). `remapped_row_failure: Yes`: block. Pending remap or pending retirement: warn with the reset text. Many retired pages: warn (read NVIDIA's RMA guideline from current release notes before hard-coding a number). Hardware or thermal slowdown active while idle: warn.
- **Fix:** "GPU `{i}` reports `{symptom}`. Drain the node (reboot first; `nvidia-smi --gpu-reset -i {i}` is destructive and needs the GPU idle), then `nvidia-smi -q -d ECC,ROW_REMAPPER -i {i}` for detail. If it returns, open a hardware case with the node vendor."
- **Fixture:** XML with clean counters and with remap failure, both ECC layouts, synthetic `kmsg` records such as `NVRM: Xid (PCI:0000:3b:00): 79, pid=1234, GPU has fallen off the bus.` with boot-relative timestamps, a healthy GPU after an old Xid, a root-less run.

## 7. Data store checks (`store`, M3)

Placement: no crate is reserved. Proposal: module `rdy-checks-net::store` behind a cargo feature, off in M1 so the alpha binary stays small. Credentials come from environment variables named in the spec (`dsn_env`, `url_env`), never from the spec text, and are read by name through the facade. Protocols run over a `ProbeStream` (`tokio-postgres` `connect_raw`, a minimal RESP client) with rustls on the ring provider; S3 goes through the `FacadeHttpClient` adapter of section 5. All sessions are read-only (`default_transaction_read_only = on` for Postgres, no write commands for Redis, no `PutObject` for S3).

| Order | Id | Tier | Privilege | One line |
| --- | --- | --- | --- | --- |
| 1 | `store.postgres` | M3 | db credentials from env | Reachable, TLS, version, extensions, grants |
| 2 | `store.s3` | M3 | s3 credentials from env | Bucket reachable, listable, versioning, S3-compatible quirks |
| 3 | `store.redis` | M3 | optional credentials | Reachable, TLS, version, memory policy, ACL |

`store.kafka` is reserved (section 9).

### store.postgres (M3)
- **Measures:** TCP, TLS support, authentication, `server_version_num`, available and installed extensions, the grants an installer needs, a few settings.
- **Source:** without credentials the check stops after the answer to an `SSLRequest` (`S` or `N`). With credentials: `SHOW server_version_num`, `SELECT name, installed_version FROM pg_available_extensions WHERE name = ANY($1)`, `SELECT rolcreatedb, rolcreaterole, rolsuper FROM pg_roles WHERE rolname = current_user`, `SELECT has_database_privilege(current_user, current_database(), 'CREATE')`, `SELECT has_schema_privilege(current_user, 'public', 'CREATE')` (PostgreSQL 15 removed the default `CREATE` on `public`), `SHOW wal_level`, `SHOW max_connections`.
- **Needs:** needs Network, env DSN, timeout 10s connect and 5s per query, 20s total.
- **Thresholds:** spec `dsn_env`, `min_version: 14`, `extensions: [vector, pg_trgm]`, `public_create: true`, `wal_level: logical`, `min_max_connections: 200`, `tls: required`. Missing version, extension, grant or wal level: block. Low `max_connections`: warn. Server requires TLS but the DSN has `sslmode=disable`: block with that text.
- **Fix:** "PostgreSQL 15 and later: run `GRANT CREATE ON SCHEMA public TO acme_app;` as the schema owner. Missing extension: `CREATE EXTENSION vector;` as a superuser (on RDS, a member of `rds_superuser`)."
- **Fixture:** a scripted Postgres wire server (`pgwire`, dev dependency, ring only) replaying recorded sessions: v13, v16, no `pgvector`, no `CREATE` on `public`, TLS-only server, auth failure. One optional CI job runs against a service-container Postgres with synthetic data.

### store.s3 (M3)
- **Measures:** S3 or S3-compatible endpoint (MinIO, Ceph RGW, R2): TLS, auth, bucket exists, region, listing, versioning, object lock, encryption setting, clock skew.
- **Source:** `aws-sdk-s3` with endpoint override, `force_path_style` option and `RequestChecksumCalculation::WhenRequired` (recent SDK defaults send CRC32 trailer checksums that many S3-compatible servers reject). Calls: `HeadBucket` (reads `x-amz-bucket-region`), `GetBucketVersioning`, `GetBucketEncryption`, `GetObjectLockConfiguration`, `ListObjectsV2` with `max-keys=1`, `HeadObject` on spec `probe_object`.
- **Needs:** needs CloudCredentials or env keys, timeout 10s per call.
- **Thresholds:** spec `endpoint`, `bucket`, `region`, `path_style`, `versioning: required`, `object_lock`, `ca_bundle`. Cannot reach, auth fails or bucket missing: block. Versioning or lock mismatch: block. Write permission cannot be verified without writing, so the result always carries "write access not verified" as a warn unless the spec accepts it (`write_unverified: ok`).
- **Fix:** "`RequestTimeTooSkewed`: the clock is off by `{n}`, fix `host.time_sync`. `SignatureDoesNotMatch` on MinIO: set `path_style: true`. `NoSuchBucket`: create it or fix the name."
- **Fixture:** recorded S3 XML responses replayed at the facade, including `RequestTimeTooSkewed`, `NoSuchBucket`, `403` and a 501 for the checksum header.

### store.redis (M3)
- **Measures:** TCP, TLS, auth, version (and Valkey), mode (standalone, cluster, sentinel), role, memory policy, persistence status, ACL rights for named commands.
- **Source:** `PING`, `HELLO` or `AUTH` from `url_env`, `INFO server`, `INFO memory`, `INFO persistence`, `INFO cluster`, `CONFIG GET maxmemory-policy` (managed services often disable `CONFIG`; then partial), `ACL DRYRUN <user> <command> <args>` (Redis 7) for spec commands. No writes.
- **Needs:** needs Network, optional credentials, timeout 5s per call, 15s total.
- **Thresholds:** spec `url_env`, `min_version`, `mode`, `maxmemory_policy: noeviction`, `commands: ["SET", "XADD"]`, `tls: required`. Version, mode or policy mismatch: block. Command denied by ACL: block. Last RDB save failed: warn.
- **Fix:** "`maxmemory-policy` is `allkeys-lru`; the product stores queues and needs `noeviction`. Run `CONFIG SET maxmemory-policy noeviction` and persist it in `redis.conf` (managed service: change the parameter group)."
- **Fixture:** a scripted RESP server replaying recorded `INFO` outputs (Redis 6.2, 7.2, Valkey, cluster), `-NOAUTH`, `-ERR unknown command 'CONFIG'`, ACL dry-run denials.

## 8. Custom checks (`custom`)

Placement: `custom.file` in `rdy-checks-host` (it only reads files), `custom.exec` in `rdy-engine` next to the executor, because it is an engine feature that runs vendor code, not a measurement.

| Order | Id | Tier | Privilege | One line |
| --- | --- | --- | --- | --- |
| 1 | `custom.file` | M2 | reads only | File exists, mode, owner, content, certificate expiry |
| 2 | `custom.exec` | M4 | whatever the command needs | Run a vendor command, compare exit code and output |

### custom.file (M2)
- **Measures:** vendor-specific files: a license, a config, a certificate.
- **Source:** facade `stat` and bounded `read`. Unix mode and owner through `native`. Content: regex over the first 64 KiB (the `regex` crate, linear time); YAML and JSON path assertions (for example `.license.expires` later than now); SHA-256 equality; PEM certificate `notAfter` through `x509-parser`. Glob matches capped at 100. Windows: mode and owner are not applicable (read-only attribute only); ACL checks are M5.
- **Needs:** wants read access to the path, timeout 5s. Unreadable: `partial`, with "run as the service user".
- **Thresholds:** spec `path`, `exists`, `type`, `mode_max: "0640"`, `owner`, `size_min`, `matches: <regex>`, `json_path`, `sha256`, `cert: {warn_days: 30, block_days: 7}`. Any assertion failing: the spec severity. The check never records file content except capture groups the spec names, and those pass through redaction.
- **Fix:** required in the spec for this check; `rdy spec lint` warns when it is missing.
- **Fixture:** a fake file tree with a good license, an expired one, a world-readable key (mode in `root.manifest.json`), a certificate expiring in 10 days, an unreadable file.

### custom.exec (M4, ADR 0005)
- **Measures:** whatever the vendor's command prints or returns.
- **Source:** the rules of ADR 0005 and `02-engine-design.md`, summarised here so the catalog is complete: `argv` list only (a vendor who needs a shell writes `["/bin/sh", "-c", "..."]` and the consent list shows it as written); declared expectations `expect: {exit: 0, stdout_regex, stdout_json: {path, op, value}}` and a maximum duration; same subprocess policy (fixed PATH, cleared environment, fresh temp directory, 64 KiB caps, process-group kill); when euid is 0 the command runs as an unprivileged user unless the check declares `needs: [root]`; Linux hardening `no_new_privs` and Landlock where available, absent on macOS and Windows, and the docs say so. This is contained execution, not a sandbox, and the docs use that word.
- **Needs:** `Need::Consent`: consent is bound to the exact command list (interactive yes, or `--allow-exec=<sha256 of the exec plan>`; a bare `--allow-exec` is refused); an unsigned spec with `custom.exec` exits 64 and `--allow-unsigned` never implies consent. Without consent the check is `Skipped`, and under block severity the run is NOT READY.
- **Thresholds:** any expectation mismatch: the spec severity. Timeout: `Timeout`.
- **Fix:** required in the spec.
- **Fixture:** synthetic commands: prints `ok`; exits 3; sleeps forever; prints 10 MiB; tries to write `/etc/acme-test`; reads the environment for `AWS_`. Run on all four CI targets. The implementation ticket is ADR 0005's.

## Decisions needing an ADR

**Hooks that `02-engine-design.md` lacks, addressed to rust-architect.** The reviewers asked for these; each is cheap now and costly after the contract crate freezes. Put each in 02 or reject it with a reason.
1. **UDP.** `permit_nameserver` covers `hickory` only. SNTP in `host.time_sync` needs a datagram permit and exchange (`Probe::permit_udp` or `udp_exchange`), with the same peer policy and action-log entry.
2. **Connect targets.** `Target` has `Host` and `Proxy`. Needed: an explicit `Addr(SocketAddr)` so `net.egress` can try each resolved address (dual stack, 250 ms stagger, per-attempt timeout) and report which family failed; `Unix(path)` for Docker, Podman and containerd sockets; Windows named pipe (M2).
3. **Record-wise nonblocking read.** `/dev/kmsg` must be opened with `O_NONBLOCK` and read one record at a time until `EAGAIN`; `read_tail` cannot do that, and a blocked `spawn_blocking` read cannot be cancelled.
4. **Exec.** (a) A kill-on-timeout that never waits for the child and returns `Hung { pid }` (a wedged `nvidia-smi` in uninterruptible sleep survives SIGKILL), in its own process group; (b) a per-command stdout cap (2 MiB for the GPU XML); (c) per-program extra search directories declared in `CheckInfo` (GPU Operator and managed-cloud paths for `nvidia-smi` and `nvidia-ctk`, `/usr/local/cuda/bin/nvcc`), since the fixed search path alone makes a healthy operator-managed node read as "no tooling".
5. **Family-scoped shared state.** One `nvidia-smi -q -x` call and one `ClusterFacts` fetch must survive a single check's timeout and must not be attributed to, or aborted with, the first check that asked. Needs a family-scoped `Probe` with the union of the family's manifests and a detached task, plus check registration through `Family::build` taking shared `Arc` state.
6. **Result fields.** `Skipped` with `caused_by: <check id>`; `Partial` with `not_evaluated: [{what, why, grant}]` and `missing_grants: Vec<String>` next to `missing: Vec<Need>`; an `evidence: Vec<ApiCall>` list with request ids; an `identifier` evidence class (account ids, ARNs) that the redactor and the upload consent treat separately.
7. **For SDK clients.** An `Http` primitive on the facade (request in, response out) that applies the proxy, trust store, allow-list and action log, so the AWS SDK adapter sits on it; `Need::Consent(&'static str)` for `--allow-assume-role` (and `--allow-exec`); `CheckContext` as `#[non_exhaustive]` with a builder and a typed extension slot; an SEC-21 exemption for the SDK credential providers.
8. **Kube guard.** Restrict the dry-run `POST` to the core `v1` `Pod` path `/api/v1/namespaces/{ns}/pods?dryRun=All` with `generateName: rdy-probe-`, and assert that in the guard test (an aggregated API server that ignored `dryRun` would persist the object). `pods/log` stays refused; `k8s.dns` works without it.
9. **Shared helper module.** Dotted version compare, quantity parsing, nominal band and severity cap need one home that `rdy-checks-host`, `rdy-checks-k8s` and `rdy-checks-gpu` can use without depending on each other (for example `rdy_engine::units`).
10. **Amendments to accepted ADRs and docs:** ADR 0006 item 5 (`getent`), ADR 0009 (builder ticket to M2, AWS feature set), ADR 0010 (proxy feature, anonymous warning, POST list, flag name, client ownership, slice split), and the 02 host coverage table (see corrections).

**Choices taken in this catalog, conservative option first.**
- Server-side dry-run in `k8s.admission`: off by default, enabled only by spec `dry_run: true` plus a user flag, core `Pod` only. Alternatives: on by default; never.
- Writes are excluded everywhere (canary PVC, egress pod, S3 `PutObject`). Alternative: an explicit `--allow-writes` flag that unlocks `k8s.egress_probe`, a PVC canary and an `store.s3` write probe.
- Embedded data files (Appendix B) updated only by release. Alternative: signed catalog updates fetched or carried in the spec.
- `assume` in `aws.*` checks needs `--allow-assume-role` or an interactive confirmation, and an `RDY_`-prefixed ExternalId variable. Alternative: implied by the signed spec.
- Vendor-role checking is read-only trust inspection plus simulation first; `assume` only when the operator is trusted. Alternative: `assume` as the primary path (fails on standard BYOC trust).
- `credential_process` profiles are not allowed (feature off, `skipped` with an export hint). Alternative: allowed behind a flag and listed in Appendix A.
- The EC2 dry-run fallback in `aws.iam` is opt-in (`probe: dry_run`), because dry-run denials are logged as errors. Alternative: automatic with a notice.
- AWS SDK crates versus a thin SigV4 client for EC2, decided on build time, size and RAM numbers from the M2 spike.
- Placement of `store.*` and `custom.*` in existing crates (see corrections) versus new crates.
- Revisit triggers for a glibc NVML build or a helper binary are recorded in section 6; no ADR is needed until a design partner asks.
