- Add `rdy verify <spec>`. It checks the signature and prints the product, key, fingerprint, trust note, signing time, revision, expiry and SHA-256, then `VERIFIED`. `--json` prints a `Verification` object. Exit 0 means `rdy run` would accept the file with no override. `rdy run --key <pub>` and `rdy verify --key <pub>` check one run against a key from the command line, print the KEY NOT PINNED banner, read no trust store and save nothing.
- Spec loading refusals now read as in the plan, with the file name inside the sentence and no `file:` prefix, and each exits 64 with its own `error.code`: `spec_unreadable`, `spec_unsigned`, `spec_key_unknown`, `spec_signature_invalid` (a file that does not match, a signature that is not in the form rdy accepts, a product that differs), `spec_expired` and `trust_store_insecure`. A spec with Windows line endings adds a note to a signature error. A root run that finds no key says it reads only `/etc/rdy/trust.yaml`. A sidecar that is there but cannot be read, is a folder or is empty is a bad signature and never "no signature", even with `--allow-unsigned`. A `--sig` file that does not exist is a usage error. `rdy-spec` adds `TrustStore::for_one_run`. The "limit is" spec errors end with a full stop.
