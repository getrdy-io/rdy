- `net.egress` now sends one `HEAD` or `GET` to a URL endpoint and checks the status against `expect_status` (with none listed, 2xx, 3xx and 4xx count except 407, see the docs). A bad status is class `http_status` and a reply that is not HTTP is `http_failed`, each with a fix. A query-string token never reaches the report. A proxy path is still to come.
- With no `expect_status`, a URL counts as reachable on 2xx, 3xx and 4xx except 407, warns on 403 (a proxy deny page looks the same) and fails on 407 and 5xx. For check authors, `rdy_engine::testing` gains `assert_cases_with`, `assert_cases_with_in` and `run_case_on` for cases that need scripted servers and spec hosts.
