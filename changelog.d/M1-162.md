- Add the `k8s.dns` check code (the cluster DNS runs, has a ClusterIP, serves the cluster domain, and shows no forward loop). It finds CoreDNS, kube-dns and OpenShift DNS by label, not by name. It blocks in two cases: when the DNS pods are not all ready, and when a CoreDNS that forwards to `/etc/resolv.conf` is crash-looping with a recent termination. It also blocks on a cluster domain that differs from the one the spec names in `cluster_domain`. A missing Service, a headless one, or no DNS found only warn or are noted. Lifetime restart counts alone never block. It only reads. It does not run in `rdy run` yet. The example read-only role gains the grants it needs in `kube-system`, and a new `rdy-readonly-openshift-dns.yaml` covers OpenShift. The kube-system Role of the example role is now named `rdy-readonly-kube-system`; remove the old one with `kubectl -n kube-system delete role,rolebinding rdy-readonly-deployments`.
