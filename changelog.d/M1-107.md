- `rdy run` now checks Kubernetes. `k8s.version` and `k8s.access` run against the cluster of your kubeconfig, which rdy reads only when the spec has a `k8s.*` check and never with `--no-network`. The cluster line (context, server, user) is printed to stderr before the first request. Without a kubeconfig, `k8s.access` blocks with the fix and the other Kubernetes checks are skipped. A credential plugin that waits for a login ends after 10 seconds and does not keep rdy from exiting.
- With no certificate authority in the kubeconfig, rdy now trusts the roots it read from this machine (else its bundled roots). `k8s.version` reads the node list only when the identity may list nodes.
